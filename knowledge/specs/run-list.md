# Run-list operation

Status: proposed design under [#1555](https://github.com/realkarych/kora/issues/1555). The owner approved preparation of this design on 2026-11-14, not runtime implementation or its final wording. No route or client mode described here is active. Existing decision records and specifications remain authoritative until this design is accepted.

This document defines one operation: `GET /api/v1/namespaces/{ns}/runs`, the shared Python client, `kora runs` and stdio `kora_runs(mode=list)`. It completes the list entry in the [bounded-read catalogue](bounded-read-projections.md#4-normative-route-catalogue). It does not activate the singleton run read, waits, selected content, events, approval responses, a worker or a scheduler.

Governing contracts are [API conventions and authorization](api-and-agent-surface.md#1-conventions), [bounded reads](bounded-read-projections.md), [run occupancy](data-model.md#131-exact-occupancy-predicates), [usage and completeness](data-model.md#7-usage-records-and-completeness-fr-91), [target identity](data-model.md#12-immutable-run-target-identity-adr-0019), [observability](observability.md), and ADR-0002, ADR-0010, ADR-0011, ADR-0014, ADR-0015, ADR-0017, ADR-0018, ADR-0019, ADR-0020 and ADR-0026 in the [decision index](../../docs/decisions/README.md). This design changes no execution or publication authority.

## 1. Request and authorization

The route accepts an ordinary personal bearer token authorized for `ns`; it needs neither `approve`, `platform` nor `transcripts`. Each page authenticates again. Existing credential, principal-kind, namespace and method precedence applies before scoped projection or cursor interpretation. A service credential is forbidden. A cursor never grants authority. An inaccessible namespace is API005; an authorized namespace name that does not exist is API001.

Query names form a closed set. Every name occurs at most once, including when repeated values are equal. Empty values, unknown names, invalid encodings, invalid combinations and invalid types return the existing API003 envelope without reflected input. A value is decoded once through ordinary query parsing; a percent-encoded separator remains part of that value. Boolean spellings are exactly `true` and `false`.

| Query | Meaning and validation |
|---|---|
| `graph` | Exact graph name in this namespace; no global graph lookup. |
| `status` | One of `pending`, `running`, `succeeded`, `failed`, `cancelled`; compares the saved run status. |
| `rerun_of` | Public run identifier; compares `rerun_of_run_id`. |
| `target` | Exact, case-sensitive target key using the existing target-key grammar. |
| `holding` | Boolean; requires `target`; tests whether `target_held_since` is non-null. |
| `target_deferred` | Boolean; requires `target`; tests the current target-deferral predicate below. |
| `recovery_required` | Boolean; tests whether any attempt of the run has `recovery_required=true`. |
| `worker`, `worker_attempts` | Both present or both absent. Worker uses its existing identifier domain; mode is `held` or `recovery`, with the predicate below. |
| `limit` | Decimal integer 1–100, default 100. Signs, whitespace, fractions and redundant leading zeroes are invalid. |
| `cursor` | One version-1 continuation described in section 3. |

All filters combine with AND. `holding=true` with `target_deferred=true` is a valid conjunction yielding no matches: deferral requires an unheld run. A well-formed absent or foreign graph, rerun parent or worker yields the same empty page; no separate globally scoped existence query distinguishes them. Invalid identifier syntax remains API003. Neither `wait` nor `wait_timeout` is allowed, including timeout without wait; both return API003.

The API owns validation. CLI/MCP forward query values separately without reimplementing these predicates. CLI exposes every filter through the existing hyphenated names and `--limit/--cursor`; it has no wait flag for this command. MCP list-mode arguments forwarded as `wait` or `wait_timeout` still receive API003 from the API. Unknown MCP modes use the ordinary tool argument error. Only actually implemented modes appear in the advertised tool schema.

## 2. Response and source map

HTTP 200 returns exactly `{items, next_cursor, observed_at}`. `items` is a list of `RunListItem`, `next_cursor` is a string or null, and `observed_at` is the UTC observation time captured after the snapshot is established. All summaries, sources and counts belong to that snapshot. There is no total count of matching runs. Timestamps use the existing UTC `Z` representation; IDs use their existing public encoding, never raw database/private identities.

All fields below are present. Null has the stated meaning, never an inferred empty value. Invalid required stored facts produce fixed API010, rather than a fabricated summary or omission of the affected run. Explicit historical absence is representable where indicated. Clients preserve unknown response fields for forward compatibility through their existing response rules; server models remain closed.

| Item field | Type and authoritative source |
|---|---|
| `run_id`, `graph_id`, `graph`, `graph_version_id`, `graph_version` | Run ID, namespace-scoped graph ID/name, and the run's pinned version ID/number from the relational joins. Never today's version in the execution-version fields. |
| `status` | Saved run lifecycle enum from section 1. `failed` can be retried; this field does not assert resource release. |
| `created_at`, `started_at`, `finished_at` | Run creation time and nullable saved execution start/finish times. Null start means not started; null finish means no saved finish time. |
| `trigger_kind` | Saved trigger's `kind`, projected as one bounded scalar; null only for history that did not record the kind. No raw trigger, event, parameters or idempotency key is returned. |
| `rerun_of` | Nullable saved parent run ID. A parent must belong to the same namespace before its ID is exposed. An inconsistent foreign relationship is an internal failure. |
| `target` | `{key, held_since, origin}`; nullable key and hold time are independent saved facts. Origin is defined below. |
| `state` | `{scope:"top_level", counts}`; `counts` contains every node status from the data-model state machine with a nonnegative exact count, including zero. Count all relational `top_level=true` instances of this run in their current state. No body-instance or old attempt status is substituted for an instance's state. |
| `admission` | `{outstanding, execution_reserved, limits, target_blockers, recovery_blockers, recheck_at, next_action}` as defined below. |
| `cost` | The compact accounting observation below, computed from all attempts/usage of the run. |

The top-level summary intentionally has an explicit scope. A running wrapper can contain live descendants; these counts do not establish that every live node is waiting, that a person is needed or that the run is settled. There is no `all_live_waiting` or human-action conclusion. The operating-reference rule for undetermined universal state remains unchanged. Pending runs before materialization have zero counts, not a synthetic pending node.

### Target origin

`origin` is null exactly when `key` is null. For a bound key it is `{state:"recorded", source, parameter, node_path, output_name, path, artifact_version_id}` or `{state:"not_recorded"}`. Recorded `source` is `param` or `output`; irrelevant fields are null, while relevant fields preserve the exact first `run.target_bound` event. The selector `path` retains its original value and type rather than becoming a filesystem path. Parameter binding has `parameter`; output binding has `node_path`, `output_name`, `path` and `artifact_version_id` according to the declared selector. These use their existing identifier/path bounds.

Read only the selected bounded origin scalars from the earliest scoped binding event in `(at,id)` order. Multiple initial-binding events or disagreement with the immutable run key is an internal failure; bounded duplicate detection is part of the same row budget. A bound legacy run with no event is `not_recorded`, not an inferred parameter/output origin. Expiry of source artifact bytes does not remove the recorded origin. No artifact body or current graph configuration reconstructs it. A selected origin too large for the item follows the ordinary projection refusal.

### Admission and filter predicates

`execution_reserved` is `has_physical_attempt(run)` from data-model section 13.1: any attempt in `created`, `claimed`, `submitted`, `running` or `finishing`, including superseded/historical attempts. `outstanding` is pending/running lifecycle OR that predicate OR a retained target hold. No lease, current-attempt pointer or logical node status releases a contribution.

For this read, a worker **holds** an attempt when its saved `worker_id` matches and the attempt is non-terminal by that same physical-status set, or its execution is `live`/`unknown`, or `recovery_required` is true. A worker recovery match additionally requires `recovery_required=true`. Resolve through attempt → node → namespace-scoped run; include historical/superseded attempts and terminal runs with retained work. Retained closed dispatcher history alone is not a hold. This is the proposed common predicate for future `/workers` and run-wide attempt enumerations; neither consumer may independently substitute current leases or current node pointers. No new dispatcher/worker authority is granted.

`target_deferred` means the run has the requested key, no hold, a pending/running lifecycle and at least one current open admission wait whose recorded reason is `target_held`. That wait belongs to an instance's current activation under the data-model wait rules. An old closed wait or historical event never matches. It describes the current saved wait, not proof that the same blocker still exists or a new scheduling decision. Legacy/unknown reason representations cannot prove true; if their interpretation is required to decide the filter, return API010 instead of treating them as false.

`limits` is an array of two closed tagged shapes. A namespace-owned observation is `{visibility:"visible", scope:{kind,id}, limit_name, limit, used, source_graph_version_id, observed_at}`. A shared-scope marker is exactly `{visibility:"redacted", scope:{kind}, limit_name}`, where `kind` is `global` or `runtime`; it has no resource ID, limit, usage, version or observation-time field. The visible rows include the namespace outstanding cap, the graph execution-run cap, and each distinct namespace-owned scope/name used by a current open admission wait in the returned run. Verify the scope's namespace ownership before projecting its identity or values. A foreign stored relationship is API010, not permission to disclose it.

This operation always redacts shared global/runtime observations, including for a token with `platform`; it grants no wider aggregate-disclosure authority. Emit at most one redacted marker per `(kind,limit_name)` named by this run's current open waits. The marker describes the run's saved wait scope, not the existence, number, value or current use of shared resources. Do not query cross-namespace aggregates to construct it. Broader administrative inspection is outside this operation. This is an explicit proposed public shape, not a disclosure policy already supplied by ADR-0020; final owner acceptance is required. Never replace a redacted value with zero or a namespace-local count.

Current namespace configuration and live graph/node policy supply visible limits; saved wait observations do not stand in for today's policy. Graph caps span all graph versions and name the highest-numbered active version, falling back to highest deployed. An absent optional graph cap has `limit:null` with current usage and cap-source version; it is not zero capacity. `source_graph_version_id` is null for a limit not sourced from a graph version. Sort by existing capacity scope order, resource ID (absent for a redacted marker), then limit name. No node-specific cap is generalized to an entire run.

Visible usage counts may span other runs in the same authorized namespace, never other namespaces. They share the page's deadline and domain-row budget. Indexes or one scalar SQL result do not exempt their contributing rows. Inability to establish an exact visible count is a refusal of the page, not an approximate value.

Both blocker fields use `{count, ids, truncated, read_ref}`. Recovery blockers are all of this run's attempts with `recovery_required=true`, sorted by attempt ID ascending. Target blockers are every other run holding this namespace/key, sorted by run ID descending, only while this run is target-deferred; otherwise the set is empty. Samples contain exactly the first `min(count,20)` unique IDs; `truncated` is `count>20`. `read_ref` is null exactly when `count=0`; a nonempty set has its scoped relative API reference, even when the sample contains every member. A target-free or non-deferred run therefore never advertises a misleading target-holder query.

Recovery continuation is the scoped run-wide attempts route with exactly `recovery_required=true`; target continuation is this list with `target` and `holding=true`, excluding this unheld run naturally. Each continuation selects the same predicate as its count/sample, subject to the existing live-page observation semantics. `replacement_blocked=true` is not a substitute: healthy executing attempts can block replacement without requiring recovery. The new boolean attempt `recovery_required` selector is an explicit inactive proposal to extend the closed bounded-read catalogue in the separate attempt-inspection deliverable; that extension requires owner acceptance before activation. All referenced routes and exact selectors must be active before the run-list route activates. This design neither changes the accepted selector catalogue nor implements the prerequisite.

`recheck_at` is the earliest non-null `wake_at` among this run's current open admission waits, or null; it is never a promised start time. `next_action` is `operator_recovery` when recovery blockers exist; otherwise `wait_for_target` when target-deferred; otherwise `wait_for_capacity` when an open concurrency wait exists; otherwise `wait_for_budget` when an open daily-budget wait exists; otherwise `automatic_recheck` when another open admission wait exists; otherwise `none`. This observational vocabulary changes no scheduler priority or budget-check order. The aggregate can report a wait whose saved reason needs a later scheduler recheck; no read changes that reason or acquires locks/reservations.

### Compact cost

`cost` contains exactly `as_of`, `observed_at`, `completeness`, `usd_estimate`, `known_usd_estimate`, `pricing_status`, `missing_report_attempts`, `attribution_gap_attempts` and `observation_gap_attempts`. They have the types and semantics of those fields in [version-1 run cost](data-model.md#74-immutable-approval-cost). `as_of` equals the page observation; `observed_at` remains the oldest latest required usage observation, including its null cases. Omit the model breakdown, not its contribution to totals or completeness. Money is canonical decimal text, never a float.

Compute from every retained attempt and normalized usage row, including superseded/failed/cancelled work. Missing agent reports, live/unknown execution, subscription amounts and gaps retain the existing distinctions. Only a genuinely empty cost-producing ledger is complete known zero. Do not recalculate prices or read vendor `source`. Unusable predecessors are fixed API010; cardinality/arithmetic limits preventing a complete projection use API002 `read_projection_too_large`; work exhaustion uses `read_budget_exceeded`. No GET writes `config_error`, repairs history or mutates an approval snapshot.

Reuse the pure accounting semantics of `ApprovalCostTotals` where the complete inputs and its model/token bounds match. Do not call `calculate_approval_cost`: it requires a writer and run lock. Batch sources for the selected run set and keep run-keyed accumulators; do not run a calculator/query sequence per returned item. Retain at most 100 run accumulators, each with at most the existing 1,024 bounded model entries, one scalar source batch of at most 100 rows plus lookahead, bounded blocker samples and the one response buffer. Admit each model/count/string under its existing field domain before retaining it. A lookahead run retains identity only until it enters the candidate set. Implementation must enumerate the concrete accumulator/scalar allocations and test their release; these cardinality bounds and the response byte limit do not claim a process-heap ceiling.

## 3. Continuation and finite work

The existing bounds apply unchanged: default/max 100 items, a 1 MiB complete compact UTF-8 response, an 8 KiB encoded cursor before decoding, one five-second monotonic projection deadline and at most 100,000 admitted domain rows. Start the projection deadline before pool admission after authentication/namespace authorization; checkout, queries, source validation, aggregation and response composition use the same remaining time. The enclosing client deadline may be tighter. Cleanup can continue after expiry under its existing owner; it cannot turn an expired result into success or be silently detached.

The version-1 cursor is unpadded base64url of compact UTF-8 JSON with exactly `{version:1, operation:"list_runs", namespace_id, filters, order:"id_desc", ceiling, after}`. `filters` contains exactly `graph`, `status`, `rerun_of`, `target`, `holding`, `target_deferred`, `recovery_required`, `worker`, `worker_attempts` and `limit`, normalized as in section 1 and explicitly null when an optional filter is absent. The request's `cursor` is never nested in `filters`; `limit` cannot change during traversal. `ceiling` and `after` are public run IDs, with `after<=ceiling`. Reject unknown/duplicate JSON members, nesting/type violations, noncanonical base64url, excessive input and mismatched bindings with API003. Namespace/filter validation precedes data queries. Cursor values are neither signed authority nor a retained snapshot; changing valid cursor bounds can only select another currently authorized portion of the same scope.

On the first page capture the maximum visible namespace run ID before filters, inside the page snapshot. An empty namespace returns `items:[]`, `next_cursor:null`. Select IDs descending, bounded by `ceiling` and strictly below `after`. Apply all predicates under the same snapshot. Membership is live on subsequent pages; a late commit or a changed filter match behind `after` can be missed. Refresh starts a new traversal. Exhaustion is specific to the last page's observation, not a commit-order watermark.

Read candidate IDs in bounded indexed batches; secondary predicate scans and all contributing rows count toward the shared budget, including nonmatching candidates and bounded lookahead. At most 100 candidate/item records and one additional lookahead are simultaneously retained. A zero-match scan cannot run indefinitely or issue an empty cursor loop. Stop before processing domain row 100,001 and refuse without a partial aggregate. Re-reading a row for another projection charges again unless the already admitted bounded value is reused. DB-internal index/page visits use the native statement deadline, not a fictitious one-row charge for a SQL aggregate.

Aggregate only the bounded candidate set as batched joins/scans. Query families depend on the operation, not a query per item. Do not load whole run documents, event payloads, graph IR, policy maps or historical plugins merely to extract a few fields in Python. Native scalar selection must check existing field domains before driver transfer. Wide native JSON scanning remains deadline-bound database work; it is not claimed independent of payload size. If a source has no suitable compact native projection, it is a named producer/index prerequisite before activation, not permission to fetch its body.

Construct and measure the envelope incrementally, reserving the actual cursor and punctuation. Stop a byte-limited page before the first item that does not fit; resume after the last emitted item, never the last inspected row. An item that cannot fit even as the only item produces API002 `read_projection_too_large` with only its already authorized identity and fixed recovery guidance. `next_cursor` is null only when the bounded observation establishes no further match. A failed lookahead/budget check refuses the page rather than asserting exhaustion. Release DB results and the snapshot before rendering or response backpressure; recheck the projection deadline after final encoding.

## 4. Database and response ownership

The API projection owns the monotonic deadline, row/workspace accounting and bounded detached result. The metadata read unit owns its connection, native statements, results and snapshot. Reuse `Database.read_snapshot(deadline=...)`, with native deadline support added at the DB boundary; the current async timeout alone is insufficient. No run/capacity writer lock or persistent cursor is acquired.

PostgreSQL uses a read-only repeatable-read transaction. Before each projection statement, set transaction-local `statement_timeout` to a positive millisecond interval no larger than remaining time, also preserving any tighter existing limit. Less than one millisecond remaining refuses before dispatch; zero must never disable the timeout. Deadline/cancellation stops new dispatches, cancels and settles the active driver operation, rolls back, and closes native portals before connection reuse. Settings revert at transaction end; no installation-wide setting changes. Bootstrap/setup statements and setting the next timeout remain covered by the original client deadline and cancellation owner.

SQLite uses the existing read snapshot and its owned aiosqlite connection. Install a connection-local progress callback before projection work, with a private monotonic deadline and cancellation flag; a nonzero return interrupts native execution. Use a finite instruction interval fixed by the implementation and qualified by the native cancellation tests. This interval is a polling granularity, not a new product timeout. Configure lock waiting no longer than remaining time, never a longer default busy wait. External cancellation also requests driver interruption; cancelling only the awaiting future is insufficient. After the active queued work settles, remove the callback, restore connection settings, finish the transaction and return the connection. A callback/interrupt must never outlive checkout or affect a later borrower. No request/cursor/content value is captured by the native callback.

Neither backend promises hard real-time interruption of an uninterruptible OS/driver operation. If closure cannot be established, keep cleanup owned and the connection unavailable for reuse; report fixed failure through existing DB lifecycle diagnostics. Do not claim successful resource release or raise deadlines. The design's [implementation evidence](../research/run-list-design-2026-11-14.md) distinguishes documented mechanisms from pending executable qualification.

Disconnect, cancellation, failure and shutdown follow the same ownership sequence. Shutdown stops new projection admission and cancels/settles owned reads. A slow response retains only its bounded response/network resources, never a DB transaction. The shared client enforces the response byte limit before JSON parsing, encodes each query value independently, closes responses on all endings and preserves current origin/TLS/proxy/redirect rules. CLI/MCP make one list call with no automatic drain or retry. CLI human output escapes terminal controls and identifies continuation; `--json` and MCP preserve the completed API value.

## 5. Activation and verification

The implementation issue owns the API route, public models, DB projection/index integration, shared client, CLI, stdio MCP, OpenAPI/parity tests and their diagnostics together. A generated TypeScript contract update follows existing generation/check ownership; no console screen or mounted MCP is activated. The [first-slice operation mapping](api-and-agent-surface.md#first-slice-operation-coverage) and product-reference activation remain unchanged.

API owns one DEBUG completion/refusal event with fixed operation, outcome/code, returned rows/bytes and elapsed time. No cursor, query, URL, arbitrary identity/value, raw SQL, payload or exception text is added. Preserve safe request correlation, stdout boundaries and failure-independent release. Unexpected cleanup failure retains its existing WARNING/ERROR owner. This is the operation's pending observability activation row; tests below supply its future evidence.

| Future integration test | Required behavior; both databases for metadata cases |
|---|---|
| `test_run_list_authorizes_each_page` | Real token/namespace/service refusals, revoked membership between pages, scoped secondary filters and method precedence; two namespaces sharing global/runtime waits preserve redacted markers without foreign counts/IDs in API, CLI/MCP or diagnostics, including with `platform`. |
| `test_run_list_filters_retained_work` | Every filter and valid/invalid combination; healthy held work, historical/superseded recovery, terminal run holds, current versus closed target waits; exact count/sample/continuation membership with 21 recovery attempts plus healthy live work, null references for empty or inapplicable sets; no inferred writer authority. |
| `test_run_list_has_one_observation` | Concurrent committed changes cannot mix status, sample/count, limit source or cost within a page; next page sees live membership. |
| `test_run_list_continuation_is_bound` | Namespace/filter/order/limit mismatch, 8 KiB boundary, duplicate fields, encoded separators, ceiling, descending order, refresh, byte-shortened page and exact exhaustion. |
| `test_run_list_preserves_accounting` | Genuine zero, missing reports, all attempt history, partial/subscription/unpriced values, late observations and explicit overflow/refusal; no price/source read. |
| `test_run_list_bounds_native_work` | Pages 1/50/100, late cursors, 10/1,000/10,000 nodes, growing attempt/usage domains, shared 100,000-row and five-second limits, exact refusal without partial totals, no full-body driver loads or N+1 query growth. |
| `test_run_list_releases_owned_resources` | Success/error/deadline/disconnect/cancellation/shutdown; actual native query interruption and settled rollback on SQLite/PostgreSQL; restored callbacks/settings, closed results/portals, subsequent ordinary progress, no DB hold during slow transfer. |
| `test_run_list_surface_parity` | Real HTTP and ASGI, CLI and stdio MCP: identical filters and JSON/errors, safe single-value query encoding, one page/request, bounded client response, interruption and safe human output; structural OpenAPI coverage. |
| `test_run_list_diagnostics_are_content_free` | Completion/refusal/cancellation and broken/blocked sink; no retained private content, clean stdout and unchanged release behavior. |

These names are implementation acceptance requirements, not executed evidence. Use real components, injected clocks and deterministic barriers; no mocks, sleeps or repeated campaigns merely to obtain a green result. Product byte/work limits, authorization, exact results and resource closure are blocking. Query plans, latency and process RSS are diagnostic unless an existing approved method makes a named check blocking. Keep applicable Linux/macOS and SQLite/PostgreSQL coverage, the existing bounded MVP policy and required final-head CI.

Activation also requires complete scalar sources for live limit observations, supported target wait/origin representations and the actual recovery-attempt continuation. Missing producers are explicit dependencies; no fabricated zero/unknown replacement or dangling `read_ref` makes the route ready. The read side may describe deferred producer states in tests without implementing their writes. The [delivery inventory](../research/run-list-design-2026-11-14.md#delivery-and-size) names these boundaries and size estimates. This document authorizes no runtime implementation, new persisted format, dependency, gate change or size exception.
