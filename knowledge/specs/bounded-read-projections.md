# Bounded artifact and history read projections

Status: normative contract; [plan and exact documentation wording approved by the project owner](https://github.com/realkarych/kora/issues/227#issuecomment-6371188973) on 2026-10-23 under issue #227. Runtime implementations and measurements remain pending their named owners. This specification changes read contracts, not stored artifact validity or execution authority.

Governing decisions: [ADR-0002](../../docs/decisions/0002-ai-first-api-and-thin-clients.md), [ADR-0005](../../docs/decisions/0005-eleven-protocols-with-conformance-suites.md), [ADR-0014](../../docs/decisions/0014-target-identity.md), [ADR-0015](../../docs/decisions/0015-web-console-design.md) and [ADR-0018](../../docs/decisions/0018-immutable-attempt-history.md). [API conventions](api-and-agent-surface.md), [saved-owner lifetimes](data-model.md#11-immutable-contracts-and-execution-records-adr-0018), [storage](protocols.md#7-artifact-storage-fr-44) and [observability](observability.md) retain their governing boundaries.

Graph-version IR/contract document reads, authoring/validation, cost/daily routes other than the target-search aggregate, session logs/opaque transcripts, worker report/upload routes and [worker-only dispatcher history](protocols.md#resumable-retained-dispatcher-history-issue-226) keep their operation-specific contracts. The sixteen-tool MCP inventory and four console mutations remain. This contract introduces no token-rate limit or global concurrency policy. Storage's 64 KiB inline threshold is independent of response budgets. Existing immutable VcsRef validation, summary and digest selection remain authoritative.

## 1. Response budgets and completeness

All byte sizes below count compact UTF-8 JSON including the envelope, before content encoding. Byte accounting applies incrementally during construction and at clients before JSON parsing; a small compressed body is not permission for unbounded decompressed input.

| Representation | Fixed bound |
|---|---|
| Ordinary metadata collection | default/max 100 items; 1 MiB response; callers may request 1–100 |
| Ordinary singleton metadata | 1 MiB response |
| Approval list | existing maximum 100 items/2 MiB, each complete immutable cost snapshot; unchanged |
| Approval detail | 2 MiB response, including its complete immutable cost snapshot; form, response, context and bound-digest map are explicitly selected values |
| Compact selected graph scope | complete response at most 1 MiB; no paginated partial canvas presented as complete |
| Large-set sample within a singleton | exact count plus at most 20 IDs and a concrete collection read reference |
| Continuation | at most 8 KiB encoded; reject before decode if larger |
| Selected content byte page | at most 64 KiB original bytes; at most 128 KiB JSON envelope with base64 data |
| Selected text preview | at most 2 KiB valid UTF-8 prefix; at most 16 KiB envelope |
| Raw complete selected content | at most 64 KiB per submitted chunk, no whole-body buffer; total size follows its existing owner contract |

Pages contain `{items, next_cursor, observed_at}`; they do not acquire a generic total count. A byte limit may shorten a page before the item limit. The cursor advances only past emitted items. Approval-list ordering, one-candidate lookahead and `approval_list_row_too_large` refusal remain exactly as already specified. For other ordinary collections, a single metadata item that cannot fit produces `API002`, `retryable:false`, `details.reason:read_projection_too_large`, with the affected authorized object identity and fixed recovery guidance. It never produces a repeating empty page, silent truncation, partial immutable cost snapshot or successful empty value. The operation-specific selected read remains available; if a required complete aggregate cannot fit, its region shows the refusal and the paginated detail path. This refusal does not change stored validity or original-content access.

Every ordinary page uses one short read snapshot for its returned rows, scalar projections, required counts and observed time. Database resources are released before provider access, response backpressure or rendering. Batches are at most 100 rows with one bounded lookahead item; query count does not grow per returned item. No metadata operation reads source/summary bodies or invokes a historical plugin. Large fields are not fetched and decoded merely to omit them later.

Existing exact blocker/pending-approval counts remain exact and agree with their sampled IDs in that snapshot. The bounded run-read wait retains its condition/final-view snapshot and 45 s cap; it does not compose histories on every recheck. A count/aggregate that cannot finish returns an explicit read refusal, never an approximate count labelled exact.

Each finite projection unit, including count/aggregate scans, has a 5 s monotonic deadline and at most 100,000 domain rows admitted to projection/count/aggregate processing; exhaustion is `API002/read_budget_exceeded`, nonretryable, without a partial aggregate. Counts and aggregates enumerate their relevant domain rows in bounded indexed batches and stop before row 100,001; they cannot hide an unbounded count/group behind one returned scalar. Internal database index/page work is bounded by the database statement deadline, not falsely claimed to equal the application row count. The 5 s deadline covers all queries and composition together, not five seconds per query. Cancellation and deadline stop further queries and close owned database work; inability to establish closure is a failure, never a successful release claim. Existing tighter enclosing client/wait deadlines prevail. These are fixed operation budgets, not measured capacities or concurrency limits. They do not cap the lifetime of an existing follow stream: each event-page construction/submission unit is bounded while its follow connection retains existing idle, cancellation, framing and authorization rules.

## 2. Continuations and observation semantics

Use stable keyset order, never OFFSET. A versioned structural continuation carries the operation, namespace, all parent identities, normalized filters, direction/order, last emitted key and an identifier ceiling captured on the first page. It contains no credential, payload, storage location or permission. Each page revalidates current authority and scope; malformed, excessive, mismatched or unsupported continuations return `API003`. No durable cursor session, independent cursor TTL, retained snapshot or long transaction is created.

The ceiling is not a commit-order watermark. ULIDs sort creation, not commit; targets can bind to an older run later. Membership/status/currentness is live per page. An entity that begins matching behind the last key may be absent from that traversal; one ahead may appear. `next_cursor:null` means exhausted under that page's observation. Refresh restarts the traversal. Immutable selected manifest bytes and dispatcher grant identities have their immutable order; changing closure/availability fields remain observations. Clients must not use a completed traversal as a frozen mutation precondition.

Orders: run/artifact/event IDs descending; approvals by the existing `(created_at,id)` descending; node-instance IDs ascending; attempt number ascending within a node, attempt ID ascending in a run-wide query; dispatcher lease epoch ascending; lineage edges by their full existing primary key `(artifact_version_id,input_name,consumed_artifact_version_id)` ascending, including scheduler-produced outputs with nullable attempt identity; target keys in case-sensitive UTF-8 byte order ascending, identical on PostgreSQL and SQLite. Public filters are closed, validated fields; none executes client SQL, paths or arbitrary predicates.

## 3. Content descriptors and selected reads

Artifact metadata preserves saved type/behavior/contract identity, semantic digest, original payload digest and size, source provenance and separate source/summary descriptors. Each descriptor names its exact metadata owner, saved contract where applicable, exact bytes digest/size, availability and owner-scoped API read reference. Availability and `content_access` are separate. References are relative API references, not capabilities, filesystem paths, provider-private values or external URLs. They cannot be used as arbitrary client request destinations.

A source owner and a derived-summary owner remain distinct even when their physical bytes/digest match. A surviving source/shared blob never revives an expired/missing summary. Historical reads never run today's plugin, re-render a request, fetch code-host content or infer an absent observed identity. `expiring`, `expired`, `missing`, `not_recorded` and `unknown` keep their existing meanings; forbidden content is not disguised as one of them.

All selected operations accept one closed representation: `format=raw` for the complete original selected bytes; `format=page` with byte offset/length for one exact range; or `format=preview` for the first text prefix. No selection defaults to complete body expansion inside a metadata response. The existing `/payload` route retains its default raw complete response, including the unmodified stdio download call. Other explicit content selectors and the new summary route default to `format=page` at offset zero; preview/raw require that format explicitly. Metadata detail without `content=` remains metadata. Source is the existing `/artifacts/{art}/payload`; saved summary is the new `/artifacts/{art}/summary`. A summary's bytes are the recorded summary result, not an alias for the source route.

A byte page returns `{owner, payload_digest, total_bytes, offset, returned_bytes, data_base64, next_offset, complete}`. `complete` means that this page reaches the end, not that this response contains the whole value; `offset:0` and `complete:true` together identify a whole-value page. Offset/length are nonnegative bounded integers; length is 1–65,536, and offset beyond the end is `API003`. Offset equal to the end returns a zero-byte terminal page. Every descriptor and selected response carries a versioned selection binding `{owner_kind,owner_id,slot,owner_revision,representation_version,payload_digest,total_bytes}`. The query parameter is `selection`; subsequent pages (any offset greater than zero) require that complete binding, encoded as a structural selector of at most 8 KiB; it is not authority. The first selection resolves mutable pointers once. Every page/chunk validates the original owner/generation, representation and digest/size rather than resolving a node's current error or another pointer again. `API002/record_content_changed` refuses obsolete mutable generations; equal bytes under another owner never substitute for the original owner or bypass its expiry. An explicit refresh makes a new selection. The raw operation can also receive the binding to pin the descriptor it follows. After reading exactly `min(length,total_bytes-offset)` verified bytes, `next_offset` is the next offset or null at the known end, and `complete` is true exactly at that end. Unexpected EOF/extra bytes is an internal/provider failure, never a short successful page. Full-value integrity requires hashing all bytes in order against the full digest. A single range does not prove whole-value integrity or valid JSON.

A preview returns `{owner,payload_digest,total_bytes,text,returned_bytes,truncated,representation:"utf8_prefix"}`. It ends before an incomplete UTF-8 code point, never repairs/replaces bytes, and is labelled a prefix even when it resembles JSON. Non-text/non-UTF-8 content has no text preview and offers byte pages/raw content. Preview text is inert; it is never a URL, JSON value, patch, equality result or executable command. No preview is automatically loaded for every list row.

Before loading any selected bytes, authenticate and check namespace, secondary owners and required `transcripts` capability. Recheck current authority and metadata-owner eligibility before each response submission unit, using the existing fresh-authority rule for follow streams. A raw chunk is at most 64 KiB; a complete byte-page/preview JSON is one bounded submission unit. Revocation/expiry after that decision can leave only the already submitted unit in flight. The existing follow-stream single-undrained-unit, no-protected-successor-queue and one-second idle authority recheck rules also apply, with owner eligibility checked alongside authority. Deployment/server intermediary buffers remain finite and their additional in-flight bytes must be measured/documented; the application unit limit is not a claim that intermediaries can retract bytes. No further unit is submitted after failed fresh validation; raw failure after headers aborts the transfer and never appends an error to content. Expected digest/length and successful stream completion distinguish a complete download. Before headers use the ordinary structured refusal.

Selected reads do not renew retention or create a durable owner hold. Open provider descriptors retain only their physical reader resource, not eligibility to submit an expired owner's bytes. Close provider streams, network responses, buffers and tasks on completion, refusal, cancellation and shutdown. Cleanup uncertainty stays owned and visible, never silently detached.

Storage adds `get_range(content, offset, length)` over #229's exact immutable content reference, returning the same closeable async byte-stream ownership model as `get`. Length is at most 64 KiB; the core clips requested length to known remaining bytes and the provider must return exactly that span or a typed failure. The core handles an empty value/end offset without opening a provider reader. Unexpected short/extra bytes cannot be successful completion. It must seek/read the requested range, not stream and discard the entire prefix. `get` remains the complete-content operation. Range bytes have no independent authority or retention. All implemented storage providers share conformance for end-of-file, invalid bounds, slow consumer, missing content, cancellation and explicit closure. Inline source/summary storage uses the same exact byte semantics without a provider call.

## 4. Normative route catalogue

Aliases in this table expand only for readability: `R=/namespaces/{ns}/runs/{run}`, `N=R/nodes/{node_path}`, `T=N/attempts/{att}`, `A=/namespaces/{ns}/artifacts/{art}`. All final references are actual routes with encoded parameters. Existing by-id scope checks remain, and an inaccessible secondary ID never becomes a cross-namespace lookup by digest.

| Route | Metadata projection and separately selected data |
|---|---|
| `GET /namespaces/{ns}/runs` | Scalar run identity, pinned graph/version, status/timing, target/binding origin, rerun parent, cost completeness and bounded state summary. Add `holding=true` and `target_deferred=true` with `target=`, and `worker=<id>&worker_attempts=held\|recovery` for all runs containing the exact namespace-visible predicate counted by `/workers`. Held enumeration includes healthy live work, and recovery enumeration includes historical/superseded attempts; no recovery-only filter substitutes for held. Preserve existing graph/status/rerun/recovery filters. No embedded node list, parameters or history. |
| `GET R` | Run scalars, admission/recovery counts/samples, current wait result, refs to nodes/reruns/events/artifacts/attempts and selected params/trigger/limits/retention. Replace `reruns[]` and `nodes[]`. `wait` unchanged except that its ordinary view uses these bounded projections. |

| `GET R/attempts` | New run-wide collection for recovery and worker-held attempts; filters replacement-blocked, worker identity/incarnation and node. Include superseded/historical attempts and terminal retained holds. |

| `GET N/attempts` and `GET T` | Page attempt identities/status/timing/recorded contract/policy revision and observed runtime identities. | `GET /namespaces/{ns}/approvals` and `GET …/approvals/{apr}` | Add target filter. Preserve complete immutable run_cost and scalar decision/actor/time/bound SHA identities. Counts and page agree in each snapshot; later pages can differ as state changes. POST recomputes existing rules and is never authorized by a preview. Wire selectors are closed: run `holding`, `target_deferred`, `recovery_required` are booleans; `worker_attempts` is `held|recovery`; `worker` is a worker ID. `R/attempts` accepts `replacement_blocked`, `worker`, `incarnation`, `node`, and `worker_attempts=held|recovery`. `R/nodes` accepts `top_level`, `parent_instance`, `element_index` (nonnegative integer), `status` (existing enum), `recovery_required` and `declared_node` (saved IR node identity). Unrelated/conflicting filters are API003; IDs and paths are encoded as individual values and scoped before lookup. Graph `scope` is `root` or an encoded JSON array of declared node IDs walking nested fan-out/subgraph bodies in the pinned IR; it never contains runtime element indexes or arbitrary filesystem/JSON paths. The compact response includes every declared node in that scope and the existing state/wait distinctions for current instances only. Workers order by worker ID byte order. Preview members are tagged `{kind:node|attempt,id,disposition:reset|recollect|cancel}` ordered by kind then ID byte order; count categories match the operation. Retry includes wrapper recollection and full-reset distinctions from the actual clear-downstream algorithm. Cancel lists the exact current operation scope. Previews are live page observations, never a frozen reviewed mutation set.

The API tables and console element contracts use these bounded projections. `run.failed.failed_nodes` retains its immutable historical count/sample; its complete-current-failure navigation is the fixed three-reference projection below; recovery collections and target histories are paged; compact run-state strips are complete only within their stated group bound.

The run/node read-reference projection for `run.failed.failed_nodes` is `failed_node_reads`, exactly three `{status,read_ref}` entries in order: `failed`, `upstream_failed`, `cancelled`. Each read reference is `GET R/nodes?top_level=true&status=<that-state>` with its scoped namespace/run. Each returns an ordinary bounded page with an independent continuation. These are explicitly selected named subsets, not one automatically merged/drained collection; clients never reconstruct the exact total by summing visible pages. The event count/sample remains the saved failure observation and is never rewritten. Node pages are current live observations and can change after retry/cancellation; they are not a frozen reconstruction of an earlier event. No new union predicate, stored event field or client domain aggregate is introduced.

Selected saved-record fields use the existing detail route with a closed `content=` selector and the same representation options. Supported selectors: R `params|trigger|limits|retention`; N `wait_spec|source_failure|error`; T `inputs|request|policy|error|reported_outcome|observation`; dispatcher detail under `T/dispatchers/{epoch}` `closure`; event detail `payload`; approval detail `form|response|bound_digests|evaluation_error|run_cost`. The selected `run_cost` is the exact complete saved snapshot and is an escape for oversized surrounding metadata, never a substitute for complete snapshots in ordinary list/detail responses. `wait_spec` selects the saved wait subscription/poll specification; `source_failure` selects the recorded scheduler failure; N `error` first resolves the actual attempt/wait/scheduler-failure owner and pins it, and cannot page through a newer current owner. T `policy` is the saved attempt execution policy, not a fabricated run policy. Bounded safe error class/code and wait-kind/deadline metadata remain inline; content-bearing text remains selected. The request selector returns the saved sealed request including its saved feedback; it never renders it again. Each selected field names its original owner and lifecycle. Existing event payload/audit values remain forever-owned events, not expiring derived summaries. No generic arbitrary JSON pointer, storage address or provider selector is accepted.

Durable selected fields, including the input manifest, need stored exact byte size/digest and a bounded-access representation before these reads activate. Existing JSONB/text columns are not assumed to already provide exact bounded byte-range access. Their writer must atomically publish the compact descriptor with the original record, or use the existing staged-content acceptance boundary before committing the reference. Backfill validates original owner eligibility and the current saved generation at atomic descriptor publication; it never revives expired/missing content or copies a different domain digest as its representation digest. A transport representation is versioned canonical UTF-8 JSON of that saved field and does not replace its domain digest or source bytes. It retains the original record's authorization and retention, and cannot create a second independently readable owner. The implementing issue must pick and test the bounded representation and backfill before enabling the route; a full-record decode followed by slicing does not satisfy this contract.

## 5. Saved manifest representation and write integration

The original immutable input-binding manifest remains authority and retains its permanent compact-history lifetime independently of the rendered execution request. Its complete saved structure supplies nesting, ordering, repeated source selections and absent/empty values; no normalized tree index, input-occurrence table or new scheduler-production identity is introduced. Existing immediate lineage edges keep their current meaning and full primary key, including outputs without physical attempts. Request sealing and historical attribution never fill missing information from current node pointers.

A saved JSON field's selected transport bytes use a versioned canonical serialization, with a separate exact byte digest and size; this does not redefine any existing domain digest. For existing JSONB/text records it preserves the complete saved logical value, not historical whitespace or JSON spelling that the original storage did not preserve. Prepare/hash/store potentially large representations outside database transactions and locks, with bounded buffers and the existing staging ownership. At the original write boundary, freshly validate exact bindings/owner/generation and atomically publish the compact descriptor. Stale preparation cannot publish and its resources remain cleanup-owned. No provider I/O, full-manifest verification or row-per-occurrence insertion is added under run/admission locks or SQLite's writer. The concrete implementing issue must prove this boundary before activation. Reuse existing metadata projections, transactions and staging; no generic owner, query, migration or backfill framework is required by this contract.

Backfill processes the original saved value in bounded restartable work, never current pointers. Its final publication validates original owner/generation and eligibility without a full reconstruction under the lock. It cannot revive expired data, renew retention or create an independent readable owner. Inability to prepare a read representation is an explicit unavailable projection, not a claim that the original manifest is absent/invalid or permission to alter scheduling/input semantics. Read operations never fall back to loading the whole JSON then slicing. Existing eligible records must have a verified readable representation before their new selected routes activate; subsequent failure is an explicit read failure with no partial success.

Engine and metadata owners measure bytes, nesting, repeated selections and large individual fields as well as node count, transaction duration and unrelated scheduler progress. Constant descriptor row count alone does not prove short transactions. No new graph/input-validity limit is introduced. The implementation must keep original manifest, descriptor and publication identity consistent through cancellation, crash/replay, stale preparation, backfill and shutdown on both databases.

## 6. Attempt comparison

`GET T/diff?against=` resolves both immutable attempt identities once and returns metadata/digest/availability comparisons, the resolved counterpart, and refs to paged config paths/output pairs. Later continuations bind that resolved counterpart, never re-resolve a default to a newer attempt. Both sides are scoped and content-authorized before content loading; forbidden content-derived differences are omitted with explicit access status.

Add `GET T/diff/entries?against=<resolved>&kind=config|outputs` and `GET T/diff/patch?against=<resolved>&scope=config|output[&output=<declared-name>]`. Patch is explicitly selected and complete or refused. `scope=config` compares the exact saved nonsecret config in each sealed request and requires transcripts; its source-byte/work budget counts each entire saved request read, including prompt/feedback, before extraction. `scope=output` requires one exact declared output name and compares only its saved StructuredOutput artifact pair with both owners' actual rights. Other types, absent pairs or incompatible selections are explicit refusals, never VCS/code-host diffs. The output selector is forbidden for config scope. JSON numbers compare exactly without conversion to lossy floating point. Canonical object keys compare in byte order, arrays replace as complete values, and equal values emit no operation; no minimal edit/LCS promise. Computation bounds: at most 1 MiB bytes per source/2 MiB combined, JSON depth 64, 65,536 visited JSON values across both sides, 4,096 patch operations, 1 MiB complete encoded patch envelope and 5 s work. Exceeding any is nonretryable `API002/diff_budget_exceeded`, with original selected-read refs; it never returns a prefix patch as complete. Missing/expired/not-recorded source data returns `API002/diff_content_unavailable` with per-side availability and original read refs; forbidden selection returns the ordinary access refusal before loading. It is never empty/equal. Corrupt saved bytes are an internal/provider failure, never a budget refusal. Paging changed-path entries is bounded by this same complete computation budget, with a digest-bound deterministic result; no persistent diff session or cache is needed. Originals remain accessible through their complete owner reads regardless of this computation limit. Textual prompt/feedback comparison uses metadata/digests and explicitly selected original text; it does not invent an unbounded textual diff API. Code-host patches remain external links, never fetched/stored by this feature.

## 7. Target cost and console behavior

The API, not the console, computes the whole-search aggregate under the existing exact Decimal/null/billing/completeness rules. The interval and concurrent-approval policy below define this projection's attribution convention. Complete immutable approval snapshots and their accounting stay unchanged.

`GET /namespaces/{ns}/targets/{key}?view=cost[&accepted=<apr>]` selects the latest applied approved request A and its immediate predecessor B by local `(approval.responded event.at,event.id)` order, with byte-order ties. Ignore unapplied responses/replays; remote approver timestamps and approval creation order are not acceptance order. Repeated successfully applied approvals, including the same revision, remain distinct anchors under the existing request-based acceptance definition. With `accepted=`, select that exact approved request belonging to the target and its predecessor; absent/out-of-namespace requests get the ordinary not-found behavior and a request of another target cannot select a cohort. Target detail uses the same local acceptance ordering. The accepted-change card displays cost only when its approval ID matches `accepted_approval_id`; on mismatch clear/refetch the affected observations, never attach another cohort's cost to that card.

The version-1 cohort is all currently target-bound runs whose local `run.created` event order is after B and at or before A, union the run containing A. With no predecessor the lower end is unbounded; with no accepted approval the aggregate is `not_recorded`, not zero. Include failed, cancelled, rejected, superseded and retry attempts of each member run. A run created before B is excluded unless it contains A. This is an explicit attribution convention: the complete cost of a reused winning run may appear beside multiple approvals, so accepted-search values are not additive across approvals. The response and UI name this cohort instead of implying a universally defined accounting interval.

Return `{accepted_approval_id,previous_accepted_approval_id,interval_rule_version,as_of,run_count,token_totals,unknown_token_fields,usd_estimate,known_usd_estimate,pricing_status,completeness,observed_at,missing_report_attempts,attribution_gap_attempts,observation_gap_attempts,billing_classes,bases}`. Maps here have only the fixed cost dimensions/enums, never per-model or per-run entries. Reuse #142/#213's exact persisted Decimal arithmetic, integer domains, null/known-subtotal semantics and once-per-attempt coverage accounting, including ever-granted-execute/affirmative-never-started rules. No float/SQLite numeric SUM, current prices, repricing, live-counter substitution or sum of approval snapshots. Overflow refuses, never clamps.

Anchors, membership, attempts, coherent usage and coverage share one finite request-lifetime read snapshot, read in bounded batches without target/run locks. Release it before response delivery. `as_of` names that snapshot observation; `observed_at` is the oldest latest required cost-source observation, null when a required observation is absent or the cost-producing ledger is empty. Later usage, valid final-basis correction or late target binding can change a later read, including decreasing USD; this is a live estimate for the stated cohort, not cost frozen at approval. Immutable approval `run_cost` never changes. Metadata/API writers persist/index the local applied-event association where needed; no new approval transition, target table or durable aggregate is introduced.

The positive 1,000-node fixture must fit the compact response without adding a blanket node-count validity limit. The graph paints only after its pinned IR and one complete selected-scope state response are ready. Events invalidate the projection rather than being applied as a guessed complete delta stream. The view keeps one dirty/due flag per displayed scope and one global refresh request in flight; refresh starts are coalesced to at most one per second per scope, and a periodic authoritative refresh runs at least every five seconds while the page is visible, so missed/out-of-order events cannot permanently hide state. At most eight graph-scope snapshots may be displayed, with one replacement response in flight for the entire view; opening another scope asks the user to collapse one first, including an over-limit address/Back restoration, which shows an explicit expansion-limit state without silently dropping scopes. Due scopes use fair round-robin rotation; repeated invalidations coalesce without advancing a hot scope ahead of others, and a failed scope releases the request slot. Each graph-refresh request has a 15 s browser-side total deadline from dispatch through headers, body consumption and validation (the 5 s projection budget plus at most 10 s client margin). On expiry abort the fetch, cancel/release its body reader and owned task, discard the replacement and mark that scope stale with a timeout; after settlement release the global slot and rotate fairly to other due scopes. A late result cannot install or restart its timer. Unresolved local cleanup remains explicitly owned and reported, never released by merely dropping a reference. Hung headers, a stalled body and repeated timeouts require functional cancellation/next-scope-progress and resource-settlement cases; this adds no numerical browser benchmark. Slow/failed requests do not create a refresh queue: the five-second interval requests freshness when work can start, not a promise that an unavailable response arrives in five seconds. No new durable event/state sequence is introduced. Expanded scopes are separate labelled observations, not an atomic whole-run snapshot.

Keep runs at 50 per UI request and the existing 1,000-event log window. Histories use one displayed page plus one replacement page; after a swap, release the old page and preserve only a bounded navigation anchor sufficient to refetch, not all earlier bodies/cursors. Search is a server filter over the named scope or explicitly labelled current-page-only. Node detail, recovery, retry/cancel members and lineage are paged and never labelled exhaustive when truncated.

Selecting an approval page explicitly selects its context, form, bound-digest map and bound VcsRef source, identified by the approval's scoped descriptor. Its header's branch/revision/external links come only from that complete authorized source, independently of summary availability. Selecting a target's accepted-change card likewise selects that card's exact VcsRef source for its external link; no target-list body prefetch occurs. These are explicit source selections, never an expired-summary fallback; it does not select every list row. Render a retained JSON value only after complete bytes/digest and structural validation within a 4 MiB selected render budget; the parser also caps depth at 64 and total containers/scalars/property names at 65,536. Values beyond this rendering budget remain valid stored content. Larger values remain available as byte pages/raw reads; show an explicit rendering limit and complete-read CLI/API reference. A fully verified renderable input manifest still shows its exact saved input IDs/selectors, nesting and repeated selections in attempt inspection/comparison. An arbitrary byte page is not a page of bindings; oversized manifests show the rendering-limit state and the complete CLI/API read reference. No incomplete form/digest map enables an approval submission. URLs become links only after the full selected value passes the saved rendering policy; prefixes never become links. Original JSON/raw API/CLI/MCP values remain unchanged, while human terminal and DOM views escape controls and render untrusted text inertly.

Every request/result is bound to namespace, identity, selected object and navigation generation. Abort obsolete reads and also reject late results; Abort alone is not a race proof. On identity/rights loss discard protected content, stop streams/timers and refetch authorized metadata. An old canvas stays labelled with its old run and has no actions under the new run header while replacement is loading. Release readers, subscriptions, query handles, timers, detached nodes and object URLs after replacement/cancellation/unmount. Facts/narrative history remains readable only while its original owner and current rights permit it; durable decisions/IDs/digests/cost remain available independently.
