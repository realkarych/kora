## 1. Payload, limits and immutable identity

`StructuredOutput` revision `1` has no parent. Its draft-2020-12 schema has `$id: urn:kora:artifact:StructuredOutput` and admits object, array, string, number, boolean and null. `number` includes JSON integers. The payload is the value itself; neither `schema` nor `data` is a reserved payload member. A root null is a produced value, distinct from no selected output, an absent artifact, an expired payload or unavailable summary. `OutputCandidate(value=None)` is distinct from an absent candidate. Schema annotations never insert defaults or coerce values.

Validation behavior: `kora.structured-output-validation.v1`; whole-payload selection and identity summary: `kora.json-payload.v1`, with selection `[""]`. The per-type descriptor includes the exact schema-byte SHA-256, every limit below and numerical/canonicalization identity `kora.structured-json.v1`. That identity names the rules below rather than mutable Python defaults. VcsRef bytes, descriptor, schema, hashes, limits and URL grammar remain unchanged.

The closed [revision descriptor](StructuredOutput.revision-1.json) has `name`, `builtin_revision`, `schema`, `parent`, `behavior`, `validation`, `canonicalization`, `compatibility`, `digest_selection` and `schema_sha256`. `validation` contains exactly `max_raw_json_bytes: 1048576`, `max_canonical_json_bytes: 1048576`, `max_json_depth: 16` and `max_integer_bits: 14000`; `canonicalization` is `kora.structured-json.v1`. `compatibility` contains exactly `execution_semantics: kora.execution.v1` and `checker_view: kora.structured-output-view.v1`. Name/revision/URN/parent/behavior/root selection are as specified above. The schema hash covers the committed two-space-indented UTF-8 [schema](StructuredOutput.schema.json) bytes with their final newline; the publication test pins those exact bytes.

The raw and canonical payload limits are each **1,048,576 bytes**, nesting at most **16** object/array containers (root container depth 1, scalar depth 0), integer absolute magnitude at most **14,000 bits**. These are new explicit StructuredOutput revision parameters, not changes to ordinary IR embedded data or database JSON. No new global integer setting or restriction on existing large-integer IR tests is permitted. Smaller transport/form/producer limits remain independently applicable; this contract does not raise them or guarantee that every harness supports every root kind.

A custom type whose saved parent chain reaches StructuredOutput inherits this frozen parent's admission domain, limits and canonical numerical rules in addition to its own saved behavior and every parent schema. A child behavior cannot waive a parent refusal. `List[T]` remains a distinct derived contract: its items use the saved T contract, while list-container admission/aggregate limits remain independently defined by the saved list semantics; element ancestry alone does not impose StructuredOutput's 1 MiB whole-artifact ceiling on an entire list. No new list-wide numeric/size contract is silently introduced by this publication.

Structural validity and individually admitted items do not make a derived `List[T]` executable. For lists whose item ancestry reaches StructuredOutput revision 1, work items 3/4/8/10/12 must first publish and obtain owner approval for immutable list-wide canonical-byte, depth and item-count bounds covering recursively nested lists and scheduler collections/exports. Save the concrete aggregate semantics and parameters in the effective contract; acceptance-affecting changes require a new identity or an explicitly supported immutable compatibility binding. Enforce aggregate bounds before full collection materialization, canonicalization, identity summarization, persistence or payload delivery, including scheduler-produced values that bypass upload. CEL's projection bounds and generic upload caps do not bound the full logical list. Until these finite semantics and their conformance/resource evidence exist, affected derived-list activation remains unavailable. This publication chooses no numerical aggregate limit and does not silently inherit the element's 1 MiB cap as a whole-list policy. Existing supported contracts are not reinterpreted; #227 response/loading bounds remain independently required.

The raw-byte ceiling applies when the admitted wire envelope is that typed value. An already decoded embedded list item has no independent raw encoding: apply its inherited canonical-size, numerical, Unicode and root-relative depth domain without inventing raw bytes or serializing it before budget checks. The enclosing list's wire/aggregate policy remains independently applicable. The conformance vectors declare inherited custom-child and derived-list item refusals.

Raw admission checks the cumulative byte ceiling before decoding and container depth lexically outside escaped strings. Strict UTF-8 JSON refuses BOM, malformed input, duplicate decoded member names, lone surrogates, nonfinite numbers and parser-limit errors. Unicode scalar values include U+0000 in strings/keys: escaped NUL is admitted and canonicalized as the six ASCII bytes U+005C followed by `u0000`; raw unescaped control bytes remain invalid JSON. Only JSON whitespace may surround a candidate text value; accepted producer values are canonicalized before upload. Exact built-in in-process scalars, lists and string-keyed dictionaries are admitted without coercion or user callbacks; cycles and non-JSON types refuse. Count/check container cardinality and remaining byte/depth budget before copying, sorting, formatting an oversized integer or materializing another full container. Do not reuse the current generic object parser's eager copies as the untrusted admission algorithm. VcsRef retains its own unchanged NUL refusal.

Successful native admission creates an owned detached value snapshot under those bounds. Caller mutation cannot change the accepted value or its canonical/digest identity. Public mutable exports and identity summaries are fresh detached views; canonicalization, hashing and summaries revalidate any unchecked/model-constructed value before use. The #446 model uses a frozen slots value with private canonical bytes and explicit native/raw factories; framework introspection supplies no payload ingress or wire contract.

Validation order is raw bytes, lexical/decode/numerical validity, bounded canonical-domain validation, then the saved effective schemas. There is at most one fixed safe shared `ContractViolation`; unknown property names, payload values and native decoder/schema exceptions do not enter messages, paths or chaining. Paths use only fixed approved field/vocabulary names and array indexes, otherwise their safe ancestor; names authored inside a custom schema are not automatically safe diagnostic names. No content-bearing error is logged. The #446 model fixes SO001 for raw size, SO002 for raw decoding/domain, SO003 for native domain or noncanonical unchecked state, SO004 for canonical size and SO005 for unsupported descriptor, with fixed messages and root paths. Native traversal follows list and dictionary insertion order; admitted snapshot keys are sorted only for canonical encoding. The general diagnostics list ceiling remains an outer bound; saved effective-schema evaluation remains with work items 3/8.

## 2. Numerical values and canonical bytes

An integer token has no decimal point or exponent and is parsed exactly. Check decimal token length before constructing an integer, then its bit length; 4,215 decimal digits are the largest possible admitted magnitude. Signed integer zero canonicalizes to `0`. A token containing a decimal point or exponent is correctly rounded to finite IEEE-754 binary64, nearest with ties to even. Overflow refuses; ordinary underflow to signed zero is accepted. Structured-channel integers stay exact; exact native binary64 floats stay floats. Boolean is never an integer. Decimal/arbitrary precision objects require an explicit producer conversion and are not silently admitted.

Integers render in exact decimal without plus, leading zeros or decimal/exponent suffix. Floats use the shortest decimal significand that round-trips to the same binary64 value; among equally short candidates choose the closest exact decimal, with ties to an even final digit. Use fixed notation when the decimal exponent is -4 through 15 and scientific otherwise; scientific notation uses lowercase `e`, an explicit exponent sign and at least two exponent digits. Fixed notation includes `.0` for an integral float. Positive/negative floating zero are `0.0`/`-0.0`. This preserves integer versus float payload identity and signed floating zero. It is not RFC 8785/JCS: all admitted integers stay exact and keys use Unicode code-point order rather than UTF-16 order.

Other canonical rules match VcsRef: UTF-8 without BOM/newline, compact separators, Unicode code-point key sorting, recorded array order, fixed JSON short/control escapes, literal other Unicode scalars, no normalization/defaults. SHA-256 covers exactly the complete canonical bytes. Canonical-wire uploads compare staged bytes to these bytes and refuse a different representation before promotion; they never rewrite addressed content.

The immutable [vectors](StructuredOutput.vectors.json) include `1 -> 1`, `1.0/1e0 -> 1.0`, `-0 -> 0`, `-0.0/-0e0 -> -0.0`, `1e-4 -> 0.0001`, `1e-5 -> 1e-05`, `1e15 -> 1000000000000000.0`, `1e16 -> 1e+16`, `9007199254740993 -> 9007199254740993`, `9007199254740993.0 -> 9007199254740992.0`, `1e-324 -> 0.0`, `-1e-324 -> -0.0`, and `5e-324 -> 5e-324`; refuse `1e400`, NaN and infinities. They also cover all six roots, Unicode ordering including supplementary characters, escaping, root-null versus missing, array order, byte/depth/integer boundaries and invalid raw strings. Raw input and canonical text are strings or explicit concatenation/repetition segments; the fixture document's decoder cannot erase token distinctions. Tests pin exact vector file bytes/hash and per-case canonical UTF-8 hashes. Repetition segments reconstruct literal bytes only; they are not a parser or canonicalizer.

JSON Schema `integer` accepts a finite float with an integral mathematical value, but does not rewrite its payload identity. CEL conversion follows the saved checker type separately: integer-schema conversion requires an exact integral signed-64-bit value; number/dyn conversion uses the existing finite-double rules. For example `9223372036854775807` remains an exact payload and can project to CEL int; `9223372036854775807.0` rounds to 2^63 and cannot project to int. Under the compatibility binding below, the standalone artifact boundary admits a large integer when no incompatible CEL projection is required; [IR section 7.5](../ir.md#75-projections-and-typed-conversion) distinguishes that artifact boundary from independently narrower producer admission. Required conversion failure is explicit, never truncation or infinity; unrelated contracts retain their existing entry interpretation. Direct and polled approvals retain their existing signed-64-bit/data-bound entry restrictions, even for unused fields; the [API approvals contract](../api-and-agent-surface.md) and [scheduler section 16.3](../scheduler.md#163-error-and-recovery-policy) retain those restrictions. The vectors declare both direct and polled approval refusals independently of artifact admission.

For the new StructuredOutput validation behavior, schema arithmetic/equality interprets each admitted payload or saved-schema number as the exact rational value of its frozen canonical decimal spelling. This covers `type: integer`, inclusive/exclusive minima/maxima, `multipleOf`, and recursive numerical equality in `const`, `enum` and `uniqueItems`; booleans remain distinct. Do not use binary64 division, tolerances or Python's rounded int/float equality for these decisions. Thus `0.3` with `multipleOf: 0.1` accepts, a 401-digit integer with `multipleOf: 0.5` accepts, canonical float `1e+23` and exact integer `100000000000000000000000` are schema-equal, and `[1,1.0]` fails `uniqueItems: true` even though its two payload elements have distinct canonical spellings. The vectors record these schema/value/outcome cases. The ordinary structural fixture validator does not prove this runtime arithmetic; the effective-schema implementation must configure/extend an existing engine and pass exact numerical conformance. This does not rebind generic behavior for unrelated artifact types. StructuredOutput's payload limit does not cap arbitrary embedded IR schema integers or total schema-evaluation complexity; existing schema-consumer admission/complexity obligations remain independently required.

#### 3.1.3. Representation and allocation accounting

Own one immutable flat tagged arena for the normalized input. Each scalar/key is a node; an array stores ordered child-node IDs; an object stores canonical ordered key-node/value-node ID pairs and its maximum key code-point length. Every node, key and child cell is bounded by normalized node accounting. No author-key hash table is constructed. Exact immutable scalars may be retained safely; caller containers and iterators never are. Native-kind admission compares built-in type objects by identity, without invoking an authored metaclass equality method.

Auxiliary allocation uses the fixed logical shapes below. A cell or row is an accounting unit rather than a Python object layout. Tuples, dataclasses or lists may implement the same logical reservation. Reservations precede allocation, never refund, and charge every recreation. The fixed algorithm permits no optional cache or duplicate index.

| Auxiliary structure | Logical reservation |
|---|---|
| Source-record ordering | `n` source-ID cells and `2n` mergesort scratch cells |
| Object ordering during snapshot | `2n` key/reference row cells and `2n` sort scratch cells for `n` members, once per object occurrence |
| Snapshot traversal | One fixed `{container_node,next_child,parent_depth}` cursor frame per entered original container, created once |
| Schema traversal | One fixed `{position,node,edge_cursor}` cursor frame per visited schema position, created once |
| Type ancestry | One three-state cell per type and one fixed `{type,parent_cursor}` stack frame per entered type, created once |
| Active snapshot ancestry | One integer native-ID cell per active container; no set/hash table |
| Original schema position | One fixed `{document,node,parent_position,edge_kind,segment_node}` row |
| Reference | One fixed `{source_position,keyword,reference_node,target_position}` row; the absent target is filled once, without unresolved/resolved copies |
| Original node-to-position index | One sorted fixed `{node_id,position_id}` row per schema position, built once directly as an immutable index in natural original-node preorder and reused; no duplicate unsorted/sorted index |
| Potential call edge | One fixed `{source_position,target_position}` row |
| Source/type lookup | One sorted `{name_node,document_id}` row per type, created once and reused |
| Closure membership | One boolean cell per document and one queued document-ID cell per document, without duplicate enqueue |
| Graph adjacency | One start-offset cell per position plus sentinel and one target-ID cell per edge, created once |
| Graph DFS | One color cell per position and one fixed `{position,next_edge}` frame per entered vertex, at most once per vertex |
| Fragment decoding | Exactly `C(reference)+1` token-pool cells and `4C(reference)` scratch bytes per decode; no second actual-token charge |
| Numerical/encoding scratch | Every explicitly owned result buffer/magnitude reserves its admitted byte upper bound before allocation |
| Integer chunk vector | Reserve one pointer cell and one append/write work unit before each chunk append. Reversing `n` cells charges `1+n` work before movement. Sign insertion reserves one pointer cell and `1+n` work before shifting the existing `n` cells |

Full reference paths materialize only in normalized reference records; ordinary traversal follows position parent links without copying complete paths per schema node. Generated reference/path/role/parameter nodes count as input. Position/reference/graph indexes over originals count as auxiliary. Encoded canonical buffers and any extra tree copy count as auxiliary bytes/cells; no engine view or copy is made. Original immutable text retains its input-byte charge, while extra UTF-8, copies and temporary bytes are auxiliary. Numerical intermediate scratch reserves `ceil(bit_bound/8)` bytes. Object headers and allocator bookkeeping are outside this metric.

The prepared holder retains only the arena, one type lookup, original position/node-to-position/reference/edge and adjacency rows, and safe accounting. Sort, ancestry, closure, color, DFS and fragment scratch is unreachable after success or refusal. No global or prepared object retains caller containers, scratch or tracebacks. An unexpected exception may retain local frames through a caller-owned traceback until the caller releases it; after disposal there is no helper-owned retainer. Existing caller reporting must not log content-bearing locals or exception chains.

#### 3.1.4. Exact primitive schedule

One operation-wide monotone work counter, auxiliary-byte counter and auxiliary-entry counter cover the complete call, without document/branch/reference resets. Reserve before each primitive or allocation. Native kind/length/bit-length reads, iterator steps, logical row/field reads and writes, scalar/node/key visits, branch/dispatch and stack push/pop each cost 1. The bulk charges below replace their internal per-action charges; add only separately named surrounding actions. Follow section 3.1.5's algorithm rather than selecting cheaper or repeated traversals. Refused results expose no accounting; successful accounting contains normalized bytes/nodes/depth, document/position/reference counts and total logical work/auxiliary reservations.

Let `C(s)` be native-string code-point length, `b(n)` signed native `int.bit_length()` without preliminary large `abs` allocation, and `L(n) = max(1,ceil(b(n)/30))`.

| Primitive | Charge and pre-allocation rule |
|---|---|
| Unicode/size scan | Charge `1+C(s)` before one scan. Reject surrogates. Quotes, backslash and short controls encode in 2 bytes, other U+0000–001F in 6, other scalars at their UTF-8 width, plus quotes |
| Known byte/string result of upper bound `q` | Charge `1+q` work and `q` auxiliary bytes before copy/encoding/slice; emit incrementally without regex/count rescans |

| Stable bottom-up merge sort | For `n` keys and `p=ceil(log2(max(1,n)))`, charge `1+2p*(n+sum C(keys))` and reserve table scratch before sorting. Each comparison removes an element, bounding its examined prefix by that removed key length per level |
| Sorted-row binary lookup | Charge `1+ceil(log2(n+1))*(1+C(query)+max_key_length)`; empty lookup costs 1; reuse the stored index |
| Integer-ID sorted lookup | Charge `1+ceil(log2(n+1))` before native-ID comparisons; empty lookup costs 1; build the node-to-position index once |
| Active native-ancestor membership | Charge `1+current_depth` before scanning active IDs in stack order; append/pop are separate |
| Base-10^9 integer conversion | Check the bit cap first. For a negative integer, reserve `ceil(b(n)/8)` magnitude bytes and charge `1+L(n)` before unary negation, retaining its sign separately. Each repeated `divmod` by exactly `10^9` costs `1+2L(n)` and first reserves exactly `ceil(b(current_n)/8)` quotient-magnitude bytes plus 4 remainder bytes. Every extracted chunk, including zero, formats for 10 work and reserves exactly 9 output bytes including padding. Chunk-vector cells and movement use their separate entry/work reservations in section 3.1.3. Sign/padding/final assembly use the result-byte charge. Zero reserves exactly 1 result byte. Logical reservations apply even if physical results are smaller. No whole-bigint `str` or ambient `int_max_str_digits` mutation |

| Pointer/percent decoder | One percent/strict-UTF-8 and tilde-escape pass costs `1+8C(ref)` and reserves exactly `4C(ref)` scratch bytes and `C(ref)+1` token-pool cells; no second actual-token reservation, URI joining or crawl. Traversal lookup is separate |
| Array-index parsing | Require canonical ASCII digits with no leading zero except `0`, with length at most the decimal digit length of the admitted array length. Before integer conversion, charge `1+d*d` and reserve `4d+1` bits; check the index bound |

#### 3.1.5. Deterministic phases and refusal order

1. Check exact DTO class, fixed binding strings, exact ten parameters and length-detectable document-count bounds before traversal. Binding/parameter mismatch is `unsupported_binding`. Check native record/name kinds and sort the bounded records once by name using the bulk sort. Duplicate names and malformed record fields are `unsupported_schema`. Never call authored attributes or mappings. The first refusal in this fixed phase order wins; an unaffordable reservation precedes the action it would admit.
2. Visit source records in name order and inline last. Snapshot metadata/schema trees in canonical object-key order and saved array order. Check an object's exact key kinds and length lower bounds before collecting bounded key rows, sort once, then visit keys/values in that order. Scan every scalar and format every numerical occurrence once, retaining encoded-size facts for later sizing. Use the active ancestry vector. Count fixed normalized wrappers/roles/parameters in final positions and refuse before a container allocation exceeds remaining node/depth/minimum-byte capacity. Detach top-level metadata/native occurrences before semantic use, without validating and then rereading a caller graph.
3. Walk every supplied original once in document/position preorder for schema positions and support. Release snapshot cursors; allocate one fixed schema cursor frame per position. A frame carries arena node/document/parent position and bounded edge cursor, never a copied complete path. Record each position, executable child edge and executable reference occurrence once with its original source position. Reuse sorted schema-map rows. Structural schema syntax remains the caller prerequisite; malformed primitive/keyword shapes required by this walk refuse without an unbounded metaschema check.
4. Process references in position/keyword order. Decode each once; use the saved name index for a cross-URN target or the current document for a local target; walk original arena rows once per pointer segment. Require the final node to be an original schema position using the sorted node-to-position index built once. Original schema-node IDs increase in the deterministic snapshot/traversal order, so construct this immutable sorted index directly from that order, checking monotonicity without another index or sort copy. Fill the reference target and create its call edge. Build original source/target paths from position parent links once per normalized reference record, charging every emitted segment/key/node/byte to the common budgets. Never expand references or trust a caller target table.
5. With the fixed type lookup, verify non-list selected ancestry ends at exact StructuredOutput revision 1. Follow parent links using one per-type three-state vector, visiting each type/link once and refusing cycles. Seed closure with the selected chain and inline schema; use a FIFO document-ID queue, enqueue once, and visit retained references/parent links in order. Refuse an absent required target or any extraneous supplied document. Derive constraint/checker roles from the verified selected chain; reference-only records add no constraints.
6. Build numeric adjacency once from child/reference edges, sorted by source then target ID using fixed-ID sorting. Run iterative three-color DFS with ascending start-position IDs and ascending outgoing target IDs, visiting every vertex/edge once and charging color/frame actions. A gray edge is `unsupported_schema`. Release DFS/closure scratch. Finalize normalized size/node/depth accounting and canonical encoding once, charging copied/encoded bytes and refusing complete-input overrun before oversized bytes materialize. Instantiate no evaluator or transformed schema.
7. Return an opaque immutable `PreparedStructuredSchemaInput` with safe scalar accounting only. It exposes no raw tree/table export, validity method, digest/summary hook, engine handle or evaluator entry point. Success establishes only preparation under this helper. Expected refusal is exactly `unsupported_binding`, `unsupported_schema` or `preparation_exhausted`, with no `SO006`, `evaluation_exhausted` or schema-false decision. Internal programming errors propagate to existing caller-owned reporting. Public representations are content-free.

#### 3.1.6. Original schema positions and closed authority

Schema-position traversal recognizes singleton schema keywords `additionalProperties`, `contains`, `contentSchema`, `else`, `if`, `items`, `not`, `propertyNames`, `then`, `unevaluatedItems` and `unevaluatedProperties`; named schema maps `$defs`, `definitions`, `dependentSchemas`, `patternProperties` and `properties`; schema arrays `allOf`, `anyOf`, `oneOf` and `prefixItems`; and schema-valued legacy `dependencies`. `$defs`, `definitions`, `contentSchema` and schema-valued `dependencies` remain positions for support/target recognition without containment call edges. `const`, `enum`, `default`, `examples` and unknown annotation data are never traversed as schemas.

Reject `pattern`, `patternProperties`, `unevaluatedItems` and `unevaluatedProperties` at every schema position, including unused definitions; data-valued lookalikes remain inert. Unknown required vocabularies and format-assertion refuse. Supported draft-2020-12 core, applicator, validation, metadata, format-annotation and content vocabularies activate no format/content assertions.

Only `$ref` and pointer-form `$dynamicRef` create executable reference targets; dynamic pointers use their closed static initial target. Legacy `$recursiveRef` is inert under draft 2020-12 and gains no executable assertion. Root `$id` remains metadata without an alias. Any `$id` at a non-root schema position refuses during phase 3, including unused definitions and paths no reference crosses. Existing local/saved-URN grammar refuses nested-resource targets, anchors, external/relative URIs, malformed percent/UTF-8/tilde escapes, noncanonical indexes, unresolved roots and pointers into data. All bound targets are original admitted schema positions; generated arena records add no authority.

Executable containment edges cover `properties`, `additionalProperties`, `propertyNames`, `items`, `prefixItems`, `contains`, `dependentSchemas`, `allOf`, `anyOf`, `oneOf`, `not`, `if`, `then` and `else`; resolved executable references add call edges. Every schema position is a graph vertex, so potential call cycles in unused definitions also refuse. Shared acyclic targets remain shared. Original true/false schemas remain untouched. Safe stock-engine false-schema/evolution handling is a later evaluation gate. A supported contradictory schema may prepare successfully without a payload-truth claim; unsupported execution schemas remain structurally representable where ordinary IR contracts admit them.

### 3.2. Initial executable schema surface

The selected architecture uses the pinned draft-2020-12 engine with a closed set of bounded handlers: boolean schemas; `type`, `enum`, `const`; numerical bounds and `multipleOf`; string/item/property counts; `required`, `dependentRequired`; `properties`, `additionalProperties`, `propertyNames`; `items`, `prefixItems`, `contains`, `minContains`, `maxContains`, `uniqueItems`; `dependentSchemas`; `allOf`, `anyOf`, `oneOf`, `not`, `if`, `then`, `else`; and closed local/saved-URN references. `$defs` and compatibility `definitions` supply schema positions. Format, content and metadata remain annotations: no format assertion, content decoding, defaults or coercion. Unknown annotation keywords do not execute extensions; unsupported required vocabularies refuse. Legacy keywords gain no assertion meaning absent from draft 2020-12.

The initial policy excludes `pattern`, `patternProperties`, `unevaluatedItems` and `unevaluatedProperties` at every schema position in the relevant closure, including unused definitions. Annotation/`const`/`enum` data is not scanned as schema. Root `$id` remains original metadata without creating an alias; nested resources and anchor targets remain unavailable under the existing closed-reference rules. Pointer-form `$dynamicRef` retains the static initial-target interpretation.

The potential validation-call graph, including schema-child/applicator and resolved-reference edges, must be acyclic before evaluation. For example, `{"allOf":[{"$ref":"#"}]}` refuses. Shared acyclic targets remain usable without expansion; repeated DAG evaluation still consumes the common work budget. Structurally valid IR outside this profile remains representable but cannot activate affected execution. This is not unrestricted draft-2020-12 support, and it does not activate derived lists or their undecided aggregate admission.

### 3.3. Exact bounded evaluation

Preparation and evaluation each use one operation-wide meter without resets at parents, references, branches or failed candidates. Reserve work and state before the primitive or allocation. Traverse schema keywords/properties in canonical code-point order, arrays/alternatives in saved order and constraints in the order above. Bound helpers, reference dispatch, frames, validator instances and execution-view expansion as well as keyword handlers. The complete future schedule must cover string/key bytes and comparisons, lookup/collisions, sorting/search, integer-limb arithmetic, powers, decimal conversion/normalization and handler/frame/dispatch work. An opaque native helper without a finite admitted precharge must be replaced or unsupported. Numerical ceilings or a keyword-entry counter alone cannot define executable support.

Numerical operations use frozen canonical decimal coefficients/exponents, exact integers and boolean separation under section 2, including integer classification, bounds, `multipleOf` and recursive `const`/`enum`/`uniqueItems` equality. Do not construct `Fraction(float)`, use tolerant division or mixed Python numeric equality. Prefer coefficient/exponent integer operations without general GCD/Fraction normalization, checking intermediate capacity before construction. Object keys compare structurally, array order matters, and payload identity independently preserves integer/float kind and signed zero. The structural schema-consistency comparator is not this schema-instance comparator. Initial `uniqueItems` uses metered pairwise exact comparison, with no new fingerprint identity or probabilistic equality. Large distinct arrays may exhaust work; an unconstrained admitted dense array gets no new item limit or eager per-item auxiliary state.

Prepared execution views preserve original saved identity and local document bases. Dialect-dispatch fields may be removed only at actual schema positions; identically named data in `const`, `enum`, `default`, `examples` or unknown annotations remains untouched. Engine evolution must retain bounded extensions for every referenced schema/subschema, including explicit standard `$schema`, without global validator-registration mutation. Bind author references to original admitted positions before transformation; preparation-created nodes add no reference authority, and reference handlers use those exact targets rather than crawling transformed documents. Stock false-schema descent formats the instance outside keyword handlers: intercept schema-position `false` or translate it to a trusted bounded always-false execution form, preserving original false identity and data-valued booleans.

Use fixed content-free handlers rather than stock eager error construction, descendant `ValidationError` lists, instance/schema formatting or unaudited helper paths. Without unevaluated annotations, `anyOf` may stop on a completed valid branch and `oneOf` after a second completed valid branch; `not` and `if` consume only completed true/false subdecisions. Unsupported input, exhaustion and internal errors propagate rather than becoming schema-false that negation could accept or a condition could route to `else`.

### 3.4. Common composition and resources

Pure preparation, closed resolution, arithmetic and evaluation belong in existing `kora.ir` modules, importing neither protocols nor concrete plugins. The planned pure `kora.protocols.effective_artifact_type` helper composes trusted installed type behavior and the prepared evaluator under existing package permissions. It is neither a registered provider nor author-selected executable code. Provider discovery/authorization and saved-record authenticity remain the deployment/consumer owner's responsibility; the policy bounds schema-controlled work, not malicious trusted installed Python.

Composition admits the owned direct value through the frozen model, preserves every required bound type-behavior check and inherited refusal, and evaluates every applicable schema before effective digest selection or summary extraction. Unknown/mismatched behavior bindings refuse before evaluation. For affected `kora.json-schema-2020-12.v1` behavior, the exact prepared evaluator supplies schema truth, or a trusted binding must demonstrably implement the same immutable exact semantics. Ordinary stock numerical validation cannot run first and falsely refuse a value that later exact evaluation would accept. Non-schema custom behavior remains independently required. Root arrays and produced null retain their frozen admission meaning.

The common result is `valid`, `invalid` or `refused`. Only `valid` supplies an owned acceptance value usable for effective extraction. `invalid` carries at most one fixed root `ContractViolation`; genuine effective-schema mismatch uses reserved `SO006`, while `SO001`–`SO005` retain their meanings. `refused` carries only `unsupported_policy`, `unsupported_schema`, `preparation_exhausted` or `evaluation_exhausted` and proves no schema mismatch ([diagnostics](../diagnostics.md#structuredoutput-effective-results)). Internal programming errors propagate to the existing caller-owned unexpected-failure boundary. No authored property name, schema/payload content or native exception chain enters public results or logs.

Preparation owns temporary snapshots/tables/buffers; the prepared-contract holder owns retained snapshots and execution views. Each synchronous evaluation owns and releases frames, counters, comparison state and temporary buffers on every result/refusal/error. Owned encoded/temporary bytes and fixed-shape auxiliary records have separate finite capacities; they do not claim a Python heap/RSS ceiling. Record fields, integer IDs/offsets and variable bytes must be bounded; copied trees cannot hide behind an entry count. Admitted input/value snapshots are separately bounded; execution views and caches count as auxiliary state. No process, thread, task, asynchronous interrupt or wall-time guarantee is introduced. Caller cancellation waits for the finite synchronous call to settle. Future consumers must bound operation slots, queues, aggregate prepared-contract retention and fairness before activation; per-output bounds do not prove a 1,000-node graph or process envelope.

### 3.5. Producer boundaries

For the one agent-produced structured output, `config.output_schema` is the producer inline schema. If `outputs.<name>.schema` is also present, it must be structurally equal as JSON (object order ignored); otherwise `IR003`. When no structured output is declared, the existing harness-only `output_schema` configuration and ReviewBundle narrative handling remain as currently specified; this change grants them no artifact authority. Human-input responses keep section 4.2's exact effective-form equality rule; wait-event `outputs.event.schema` supplies its inline schema. Command `output_file` validates the declared output's effective contract. `List[T]` remains a separate derived type and preserves item contracts. Existing scalar parameter bindings and List[Hypothesis] examples keep their meaning. The schema belongs to the saved contract, not a payload wrapper ([IR section 3](../ir.md#3-nodes)).

The preservation guarantee starts at the selected typed producer value admitted into its owned snapshot. Generic upstream `inbound_event.payload`, `wait.observation` and `approval_request.response` retain their existing source semantics before that boundary; this contract does not newly promise to preserve earlier wire-number tokens or a signed zero already normalized there. A delayed scheduler producer admits the value from its retained source, then freezes the typed artifact once; it never invents original bytes or recomputes an accepted artifact through a current provider. Both-database source-to-output conformance must distinguish this boundary from full ingress preservation. Earlier source persistence semantics remain unchanged; narrower producer domains remain visible rather than being advertised as support for every admitted artifact value.

Harness-specific absence/capability semantics also remain: an adapter must not turn an absent/null sentinel into a produced JSON null. Existing allowed strict-text selection may produce null when the text is the JSON value `null`; unsupported root capabilities refuse explicitly under the existing harness rules. `test_structured_output_harness_absence_is_not_null` is a pending activation gate. The existing outer optional `SessionResult.output` and inner `OutputCandidate.value` already distinguish an absent candidate from a selected null without a new DTO.
