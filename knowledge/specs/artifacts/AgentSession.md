# AgentSession revision 1

Status: published under issue #433 on 2026-10-29. The project owner [approved the complete amended plan and exact human-document wording](https://github.com/realkarych/kora/issues/433#issuecomment-6507248049). This publication freezes the contract. The standalone model is implemented under #453; providers and consumers retain their named activation gates. Governing decisions are ADR-0008, ADR-0009, ADR-0010, ADR-0011, ADR-0018 and ADR-0019. Existing VcsRef, StructuredOutput and CommandResult revisions and implicit output roles are unchanged.

## Representation and authority

The primary payload is the opaque harness transcript. The artifact version's `storage_ref`, `size` and full `payload_digest`, when recorded, identify its actual retained transcript bytes. No transcript table, caller-selected storage address, executable schema or new endpoint is introduced.

The schema `urn:kora:artifact:AgentSession` describes a closed logical validation value with `metadata`, `denials` and `transcript` members. It is a materialized view used to define validation, canonicalization and complete result identity. It does not declare a multipart layout, make this JSON the primary stored payload, or authorize a filesystem/network read. The implementing model and API plans must supply the concrete owned representation and transfer mapping before activation. In particular, the existing 16 KiB multipart `meta` cap cannot carry this potentially larger logical value and is not raised here.

`metadata` is an immutable snapshot: configured harness; reported installed version and session id, each null when unobserved; nullable observed billing class; normalized per-model usage and coverage; the pinned price revision id; turn count; integer millisecond duration; stop code; and worker/image provenance. A local runtime with no image records null; no installed version, zero usage, model attribution or successful completion is inferred from missing evidence. The installed version comes from the verified installation/adapter observation, turns from kora's distinct-message count, and duration/provenance from the worker/supervisor, validated by the API. Strings are observations, never executable paths or credentials. A session id is a resumable handle only under the runtime's existing resume capability and available checkpoint; the artifact grants no resume authority.

The denial sample is the existing bounded content-free `PermissionDeniedData` shape, with at most 1,000 items, total count and completeness. Its total is at least its item count; a complete harness-denial report is not a claim that every denied call fits in the sample. The existing source/code/pattern rules are preserved: a harness denial has no pattern and one of `harness_rule`, `policy_error`, `policy_timeout`; policy denial codes cannot be `allowed` or those harness codes; a policy pattern, when present, is a `.deny.` rule id and occurs only with `denied`. There is no tool input, reason text, exception text or extension map. The sample is excluded from permanent session metadata and CEL even though its admitted events are content-free. Existing promoted content-free audit events retain their independent event owner and lifetime; this publication does not delete or reclassify them.

The complete logical value binds every field this artifact defines. Other `SessionResult` fields keep their existing owners: `output` becomes the separate declared StructuredOutput-derived output; terminal/error class, terminal reason, API error status, output diagnostic, error summary, unconfirmed calls and policy-bypass details remain attempt/report/journal evidence. Opaque `UsageRow.source` remains independently bounded usage evidence and is never copied to AgentSession permanent metadata or its CEL view. Omitting these separately owned records from this artifact is not a claim that their effects are covered by this artifact digest. An agent still owns its implicit `session`; command `result`, human `response` and wait-event `event` keep their established roles.

## Immutable bytes and complete replay

The descriptor freezes the schema-byte hash, representation, validation, canonicalization, approval-selection, summary and CEL policy identities. A changed schema or behavior requires a new revision/identity. Deployment saves these definitions by value under ADR-0018; unsupported or mismatched interpretation refuses before the affected effect. The initial AgentSession binding explicitly uses `kora.agent-session-view.v1` under `kora.execution.v1`; no previously saved contract or projection is silently repaired or reinterpreted.

The full logical value contains integers, strings, booleans, null, arrays and closed objects. Integers are exact; booleans and coercible float/string inputs are not integers. Canonical JSON follows the already published `kora.structured-json.v1` rules, including Unicode key order, escaping, no normalization and preserved array order. The per-model array is sorted by exact model name and contains each model once; `known_token_fields` is sorted and unique. Denial items retain the supervisor's observed sample order. Timestamps use the existing cost Timestamp UTC-Z serialization. The schema is structural; strict duplicate-member/UTF-8 checks, exact integer token admission, source predicates and cross-field/provenance rules remain semantic validation obligations.

The owner-approved AgentSession-specific limits are 4,194,304 bytes each for raw and canonical logical JSON and depth 16. They apply to the logical metadata/descriptor value, not opaque transcript bytes. They do not increase any transport limit or apply to other artifact/list types. The existing maxima remain 64 models, 1,000 denial samples, 256-character protocol/accounting identifiers, signed-32 token counts, exact-JSON observation sequences, signed-64 Count fields and canonical decimal money. The contract reuses the accepted protocol Identifier and cost Identifier predicates without changing them; their model/schema agreement and immutable binding must be pinned by the model follow-up, rather than inferred from this structural schema. The owner-approved `duration_ms` is floor of the nonnegative monotonic session duration in milliseconds, fitting Count. The project owner approved these size/unit choices on 2026-10-29.

Define `logical_output_digest = SHA256(canonical_logical_value)`. It binds metadata, the entire denial sample and its flags, transcript capture state, original source declaration and actual retained byte identity. It excludes operational availability and storage/provider aliases. Save this compact digest together with the exact effective output `contract_digest` permanently. The physical transcript `payload_digest` stays the full SHA-256 used by storage ownership/admission/deletion fences. It is never replaced by the logical digest.

The type selects `[""]` under `kora.agent-session-logical.v1` for approval. Thus revision 1's approval digest equals its complete logical digest by deliberate full selection, while their roles remain distinct. The storage digest is generally different. Future approval selection cannot weaken complete replay. Every approval-dependent fact must be represented by the selected saved binding; a transcript digest is identity evidence, not proof of provenance or permission to read it.

A first accepted physical output is write-once by `(attempt_id, output_name)`. After current authorization, compare its saved contract plus complete logical digest on replay. Changed metadata, denial completeness/sample, usage snapshot, capture state or source declaration conflicts even with identical retained transcript bytes. Equal replay returns the original status/availability read-only, without new artifact rows, promotion, summary/projection recomputation, retention renewal or source-result acceptance. A changed source declaration cannot hide behind a matching prefix digest. Unknown or malformed candidates may refuse earlier; they can never replace accepted identity. Preserve source staging and atomic whole-result acceptance, cancel/clear/deadline authority and historical late writes under ADR-0019. The implementing API plan must extend the existing complete-payload replay exception explicitly; it cannot silently overload `payload_digest`.

## Transcript size, integrity and availability

`capture: captured` records declared original `source_size`/`source_sha256`, whether the complete source was verified, actual `retained_size`/`retained_sha256`, and `truncated`. The retained bytes are always completely verified before acceptance. Without truncation, source and retained size/hash agree, `source_verified` is true and retained size is within the existing 256 MiB cap. A real empty transcript has size zero and SHA-256 of empty bytes; it is different from no transcript.

Over-cap truncation keeps the existing API rule unchanged: at most 268,435,432 source bytes followed by the exact 24 ASCII bytes `\n[transcript truncated]\n`, total 268,435,456 bytes. Record the larger original declaration, `truncated: true` and `source_verified: false`. Do not claim verification of the unreceived source tail or fabricate a whole-part receipt. The incomplete prefix cannot publish directly; core verifies the complete prepared retained candidate under #224/#229, saves the original-to-retained completion binding and stops further source transmission. A transcript exactly at the cap is complete and receives no marker. Truncation is not later retention expiry.

`capture: unavailable` contains no invented zero size, empty hash or storage address. It records that no transcript was captured for this logical result; this never becomes a captured-empty transcript on replay. The public reader can report `not_recorded` from that immutable capture fact. For captured content, operational availability remains the existing `present`, `expiring`, `expired` or `missing` state; a missing expected blob is an integrity/availability failure, not originally unavailable capture. The implementing data-model plan must map the existing physical descriptor's absent fields explicitly; this publication does not add a payload-state enum or pretend a migration exists. Availability changes never change identity, restore an owner or renew retention. A consumer requiring complete transcript content refuses unavailable, missing, expired or truncated evidence rather than substituting a prefix or current data.

## Usage snapshots

The artifact records the normalized finalization snapshot, including an empty usable-row set with explicit attempt coverage. Each usage entry copies the accepted UsageRow observation identity/order/time, known dimensions, TTL split, basis, billing class, normalized reported USD and resume-delta flag, excluding `source`. API/engine code derives `usd_estimate` from those exact observations and the attempt's already pinned immutable price revision. Callers cannot provide authoritative derived USD. The logical schema describes the accepted artifact view, not a worker request accepting this field. The implementation must fix the producer-to-accepted-view mapping before activation; no live ledger read or current-price lookup may silently substitute a later observation during replay.

Existing accounting invariants apply unchanged: unknown is not zero; reasoning is a subset of output; known cache-TTL sums agree; models are unique; complete coverage has no gaps; no model attribution is guessed; subscription derived USD is null even with reported vendor cost; missing required dimensions/rates remain null; known interrupted usage stays partial; resume reports deltas under its existing capability. Snapshot completeness reflects the finalization evidence and cannot be inferred from successful execution alone. Source revision/time and price id remain identifiable.

A later authorized ordered usage report may improve the independent usage ledger, including its single supported final-basis correction. It never rewrites the published artifact, its logical/approval digests, saved projections or an existing approval `run_cost`. The latter remains engine-owned aggregation across every relevant run attempt under ADR-0010; a session artifact is never its accounting authority. Snapshot validation does not itself mutate usage rows, admit a grant or certify quiescence.

## Retention, access and permanent CEL view

The transcript retains its existing run transcript owner/default of 30 days after completion, active/recovery holds and physical-store/full-byte-digest shared-owner deletion fence. The denial sample is separately retained under the shorter resolved transcript/artifact-payload period; the project owner approved this ancillary lifetime/access decision on 2026-10-29. Its compact hash/identity survives expiry, while its actual sample copy is removed. Original source declarations and completion identity remain compact metadata, never a new retention hold. No full logical JSON copy containing the sample may survive as permanent metadata.

The API owns current namespace/object and `transcripts` checks before selected transcript or denial-sample reads and during streaming. The read proxy never returns a caller-authoritative provider ref or presigned redirect. A digest or stored reference grants no access. Foreign, missing-capability, expired, revoked and stale-grant paths retain the existing structured API refusals and stream-abort rules. Transcript-equivalent content cannot leak through summaries, CEL, diagnostics or inline historical copies. Existing content-free denial audit projections retain their already accepted rights independently; this publication does not grant a new read.

`kora.agent-session-view.v1` is the permanent flattened session-metadata view fixed by `AgentSession.cel-policy.json` and its closed checker schema. It permits only harness/version/session id, billing class, normalized usage counts/known dimensions/TTL/completeness/derived estimate/basis/billing/resume-delta, usage completeness/gaps, turns, duration, stop code and worker/image provenance. It excludes reported vendor cost and opaque source, observation IDs/sequences/times, price revision identity, denial sample and completeness, transcript content/descriptor/reference/capture state and operational availability. These exclusions fix safe interpretation of the preexisting conceptual allowlist; they do not expose a full metadata wildcard. The project owner approved this exact flattening and nested allowlist on 2026-10-29.

Core validates the complete logical value, constructs this fixed view, then applies each deployment-frozen projection path set and existing CEL data/conversion bounds. It must never cut arbitrary logical-value fields directly. Whole-root, dynamic-key, collection/export, previous-attempt and presence reads cannot bypass the view; forbidden reads are `IR011`. A permitted projection exceeding the existing CEL bounds refuses, with no truncation or absent-data substitute. The saved projection's identity binds the frozen type/view/path-set semantics and remains available after transcript expiry. A missing/mismatched projection remains `projection_unavailable`; historical reads never recompute it with current schemas.

`kora.agent-session-summary.v1` returns a detached copy of this content-free fixed view for API/console use; summary and CEL projection remain different saved products with different purposes. Neither contains transcript references or denials. Current authorization still controls metadata reads. Source transfer, database fidelity, provider parity, collection/export and retention evidence remain pending the owners in the implementation plan. The standalone model boundary below records native model admission and detached summaries.

## Standalone model boundary

`kora.ir.AgentSession` owns immutable canonical logical bytes with strict native/raw admission, complete logical digest and exact revision-descriptor compatibility. Values and summaries are detached. Every public helper revalidates unchecked instances. The shared structured JSON codec accepts an explicit 4 MiB budget only for AgentSession; the existing StructuredOutput and CommandResult defaults remain 1 MiB and depth 16 remains unchanged.

Model admission preserves the existing protocol/accounting identifier predicates, exact integer and canonical timestamp domains, usage/coverage consistency, sorted unique models and known dimensions, and denial source/code/pattern rules. Locally decidable cost consistency is checked: subscription estimates are null, non-subscription harness-basis estimates equal reported USD, and table/gateway estimates are null when required dimensions are unknown. The model consumes an accepted logical view. It does not derive authoritative prices, certify observations or map a worker request into that view.

`verify_agent_session_transcript` checks supplied exact bytes within the existing 256 MiB retained limit against complete retained size/hash and, when truncated, the exact marker. It performs no lookup, decode, full-payload copy or source-provenance assertion. Empty retained content has the actual empty-byte hash; unavailable capture is distinct. The original declaration remains part of logical identity even when its complete source was not received.

`summarize_agent_session` emits exactly the frozen detached metadata view. No denial sample, transcript descriptor, reported vendor cost, observation identity/time or price-table identity enters it. Fixed `AS001`–`AS006` root ContractViolation messages exclude supplied content and parser exception context. Pure model helpers configure no logger or external resource owner.

The [model evidence record](../../research/agent-session-model-evidence-2026-10-30.md) records acceptance and diagnostic limits. Concrete producer/accepted-view mapping, API authorization and whole-result replay, storage and separate transcript/sample retention, saved CEL projection and all derived aggregate activation remain pending the owners above. The transient complete logical model is not a permanent database representation.
