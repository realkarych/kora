# Initial admission source accounting

Scope: native acquisition and complete detached source preparation under #1542. This record separates database input admission, returned native buffers and detached processing. The [scheduler contract](../specs/scheduler.md#initial-admission-source-readers-1542) governs eligibility and ownership. None of these reads creates an attempt, reserves execution capacity or makes a final admission decision.

## Shared graph acquisition

`engine.graph_snapshot.acquire_graph_snapshot` borrows the caller's coherent connection. It preserves the existing Claim reader's order: validate graph read admission, read the supported SQLite encoding when applicable, project the admitted graph fields, then acquire the bounded resource-owner inventory. Its immutable result contains the graph pair and three digests, native resource bytes and resource owners. It creates no transaction, task, thread or cache. The existing Claim composition owns its deadline, statement guard, snapshot settlement and diagnostics.

The scheduler composition reserves the run-pinned execution version and independently selected live cap version before checkout. They can differ; same-version sharing reduces actual retention without increasing either allowance. `engine.admission_snapshot.acquire_admission_snapshot` owns the deadline, statement guard, snapshot settlement and diagnostics for this consumer. Its approved [walking-skeleton PostgreSQL exception](../specs/first-slice.md#skeleton-depth) covers both versions without claiming a shared migration lease or automatic remote drain.

## Candidate owner projection

`read_admission_candidate` performs at most two exact point reads: node ID to run ID/path/status, then run ID to namespace/graph/version IDs. Invalid request identity or row allowances issue no statement. A refused node prevents the run read. Every query result closes before the next query, and the helper verifies that the original active transaction still owns the observation before returning.

SQLite uses the existing canonical-key partial indexes in `main`. Before evaluating initial-node/run predicates and projecting variable-width values, each projection admits the complete stored row. The allowance includes storage widths of every column plus `9 * (column_count + 1)` bytes for the maximum record header. Native null, integer and real values charge 0, 8 and 8 bytes; other storage classes use `octet_length`. PostgreSQL projects schema-bounded scalar fields without reading node or run JSON. Its unchanged schema is part of the trusted database boundary.

Each projected text value is separately limited to four bytes per allowed character before transfer. SQLite first requires text storage within that native-byte limit, then checks the character limit and excludes NUL before returning TEXT. Its native UTF-16 width does not by itself bound the driver's UTF-8 transfer; the nested character check supplies that bound, while NUL exclusion prevents SQLite's character count from stopping before a retained suffix. PostgreSQL's character-bounded schema and scalar predicates already bound the projected text, with the byte guard retained. The maximum projected payloads are:

| Point read | Projected values | Maximum text bytes before application validation |
|---|---|---:|
| Node | Run ID, node path, initial status | `4 * (26 + 2048 + 7) = 8324` |
| Run | Namespace ID, graph ID, pinned version ID | `4 * 3 * 26 = 312` |

Application validation requires canonical identifiers, a nonempty path of at most 2,048 characters without NUL, and one of the three initial states. The node ID is the already validated caller value. The returned immutable object retains only those scalar values and their fixed structure, not the row/result or source JSON. Aggregate composition must account for both temporary rows and the returned structure; these text figures are not process heap or RSS bounds.

## Price selection

`read_admission_price_id` performs one latest-effective namespace lookup and, only when no such row exists, one latest-effective global lookup. Both retain the version-1 partial-index predicate and `LIMIT 1`. Projection admits at most `4 * 26 = 104` bytes for the selected identity before canonical validation. A present row with an invalid identity returns unavailable without a global lookup. Selection does not read a price map or infer that it is valid; the separate native price acquisition refuses unavailable or oversized selected data without an older-price fallback.

Native query plans are diagnostics. SQLite cases verify the expected compact locator and price indexes. PostgreSQL may choose a sequential scan for small fixtures; neither an observed plan nor a latest-row result establishes a universal MVCC tuple-visit, execution-time or RSS bound.

## Aggregate native and returned representations

`AdmissionSnapshotLimits.reservation()` validates exact positive integer allowances, rejecting booleans, values above the native signed range and parameter/projection allowances above the existing 4 MiB run-parameter limit. The complete graph-read reservation validates the graph's internal allowances. Native admission and returned representation admission remain separate from later decoding and preparation.

Let `N` be the per-graph native allowance, `I` the canonical graph-pair allowance, `P` its physical-input allowance, `O` the owner-text allowance, `D` the 64-character digest width, and `R`, `J`, `Q` the run-parent, input-projection and parameter allowances. Let `V` be the candidate node-row allowance. Existing Claim readers provide `PRICE_ROW_BYTES` and `POLICY_ROW_BYTES`; their sum is charged in both envelopes. The native price allowance is 96 times the accepted canonical price revision size; the policy producer's conservative native allowance remains 64 KiB. These existing producer obligations and reader guards are unchanged.

The fixed scalar allowance is `4 * (PATH_LENGTH + 12 * IDENTIFIER_LENGTH + 2 * NAME_LENGTH) + 128 * 8`. The identifier inventory covers the requested node; run, namespace, graph and execution version; selected price and live-cap version; both observed wait IDs and their two possible attempt IDs; and the price namespace. The path and bounded state/kind fields are charged separately. The 128 eight-byte logical slots cover the retained binding/bundle references and fixed query metadata, including observation/deadline times, policy/version numbers, booleans and the bounded price timestamp. These are conservative representation charges, not Python object sizes or an allocator model. Wait and cap scalar domains come from existing canonical writers and the trusted migrated schema; arbitrary manual database replacement is not a supported producer.

Each graph additionally reserves `(MAX_OWNER_ROWS + 1) * 64 * 8` fixed bytes. The native width prefix observes at most 65 rows of two scalar cells; successful transfer contains at most 64 rows of ten cells. The temporary result/tuple inventories, the nine-cell retained owner tuple, short-lived validation fields, sequence references and fixed marker together fit below 64 logical slots per observed row. All seven variable byte fields charge the separate `O` allowance. Tuple conversion and the retained slice reference their bytes rather than copying them. The extra prefix row is charged even when rejected. This fixed-count accounting establishes bounded inventories, not process memory consumption.

With `F` equal to the price, policy and fixed scalar allowances and `W` equal to the owner-text plus owner-slot allowances, the envelopes are:

- Native: `F + 2 * (N + W) + V + 2 * R + J + Q`. The two parent charges cover candidate ownership and the later run-input parent verification.
- Returned representations: `F + 2 * (transport_limit(I, 2) + 6 * D + P + W) + Q`. The existing transport helper includes the graph pair's maximum supported expansion and envelope overhead. Three digests each reserve two bytes per character for SQLite UTF-16. Physical resource bytes have their own `P` allowance. Parameters already use canonical bytes.

The immutable result contains no query result or database row. The native unit owns intermediate values until settlement; its caller owns returned bytes afterward. Source guards precede their payload projection, while aggregate admission precedes checkout. No JSON tree, canonical rerendering, checked graph or prepared Claim belongs to this native acquisition envelope. The complete preparation owner below includes these retained bytes and both possible decoded graphs before checkout. Its #1446 consumer keeps the derived charge through transaction settlement and releases the observation on every exit.

## Complete detached source preparation

`engine.admission_preparation` admits the entire source operation before native checkout. It adds two independent `execution_contract_read_reservation` inventories to the native and returned envelopes, even when the acquired versions later coincide. It invokes the existing complete checker, then the existing readiness and cap preparers outside the reader. Same-object sharing avoids a redundant checker call but never reduces initial admission. No optional parameter-schema arena is enabled. A provisional native digest is a consistency input; accepted-run identity and current-cap authority remain the original writer's responsibility.

The method counts logical scalar payload and object/member/frame slots, not Python heap, RSS, allocator behavior, opaque Pydantic allocations or elapsed time. It uses the existing preparation method: decode `12w`, render `36w`, typed conversion `292w + 45`, auxiliary traversal `12w` and work `32(w + 1)^2` per listed operation. Decode includes scalar payload and container/member frames; render includes quoted/encoded/joined text, fragments, iterators and decimal conversions; typed conversion allows two model candidates, field/provenance containers and the largest inherited 20-field IR model. Alternative representations are summed rather than taking a smaller peak.

Let `I` be the smaller of the graph-pair and logical-IR allowances, `Q` the native parameter allowance, `N = 65,536` the existing namespace native bound, `P = 96 * 65,536 + 6` the price native bound plus compact wrapper syntax, and `D = MAX_DIAGNOSTIC_BYTES` the existing first-slice diagnostic limit. Policy compact wrapping likewise uses `N + 6`. All these are finite input bounds; the price's accepted typed canonical limit remains 65,536 bytes.

| Inventory | Widths and operations |
|---|---|
| Decode | `I, I`: readiness/cap `read_document`; `Q`: duplicate-aware parameter JSON; `P`: native price compact wrapper; `N + 6`: native policy compact wrapper; three `N`: the JSON decodes in policy `prepare`, `__post_init__` and `value` |
| Render | `I, I`: canonical document comparisons; `Q`: canonical parameter byte comparison; `P, N + 6`: native decoding/compacting/wrapping; four `N`: policy canonical renders |
| Typed | `I, I`: complete readiness/cap IR models; `P`: price revision and nested rate models, their bounded fields and owned mapping conversion. Using native width here conservatively exceeds the accepted 64 KiB typed-price width |
| Auxiliary | `I, I`: readiness topology/maps/sets/final descriptors and cap traversal; `Q`: parameter bounded traversal; `P, P`: price preflight before/after validation, including nested rate traversal; `N, N`: policy native-value-bound traversals; `2 * DIGEST_LENGTH`: provisional digest decoding; `128`: price timestamp |
| Diagnostics | One first-slice collection at `D`, with typed and rendered representations and separate work for each |
| Fixed owner | 512 logical units for fixed prepared-owner fields, scalar wrapper dictionaries, scope/pin/cap records, function frames and inventory references; bounded variable scalar payload already belongs to the native envelope |

The total retained charge is `512 + native + returned + 2 * graph_retained + 12 * sum(decodes) + 36 * sum(renders) + sum(292w + 45 for typed widths) + 12 * sum(auxiliary) + 292D + 45 + 36D`. Total work is `512 + 2 * graph_work` plus the quadratic charge for every listed decode, render, typed and auxiliary operation and two diagnostic operations. The formula validates the existing component limits and exact positive integer retained/work allowances before checkout. The ordinary source limits and complete checkers retain their own guards.

The returned frozen observation retains the original native snapshot, checked execution and live-cap graphs, readiness/caps, validated whole price, canonical policy document and the derived retained charge. The native snapshot retains both graphs and canonical parameter bytes; parameter validation's mutable tree is discarded. No caller-provided unexplained owned charge substitutes for this inventory. The #1446 operation retains this charge until its writer settles and must separately admit fresh parameter decoding/canonical validation and complete Claim preparation before materialization. Spent source-checking work supplies no preparation credit.

`test_admission_preparation_checks_complete_sources_after_release` observes the real checker/codec entries with the existing Python profiling mechanism and requires zero database units at each call, alongside actual HTTP publication/manual acceptance and unchanged metadata. It covers same/distinct graph versions and independent live caps. Unicode native source cases cover PostgreSQL UTF-8 and SQLite UTF-8/UTF-16. Malformed selected graph/policy/price cases retain the fixed private refusal without fallback. Exact/one-unit-short tests are supplemented by independent fixed allowances: 7,000,000,000 retained units and 17,000,000,000,000,000 work units permit the envelope with one checker omitted but refuse the required two-checker inventory before any checkout.

At the current test graph limits the complete reservation is 7,756,257,108 retained units and 19,355,274,134,461,530 work units; removing one checker would yield 6,983,401,780 and 15,976,404,224,083,485. These large conservative logical allowances are not allocation or runtime measurements. The independent review inspects the concrete inventory; test comparisons alone do not establish its completeness.

The owner yields at a cancellation checkpoint after synchronous preparation, then rechecks the original monotonic deadline before returning. It promises no preemption during the synchronous checker. Deterministic handoff tests observe prepared-object construction, verify reader release, then either cancel the actual task or advance the configured test event loop to the original deadline. These observers replace no production function or value. Native-acquisition cancellation and unavailable diagnostic sinks retain actual release checks. Lifecycle outcomes are not physical-memory or scheduling-latency guarantees.
