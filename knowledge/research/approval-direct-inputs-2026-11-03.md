# Direct approval input checking

Date: 2026-11-03. Implementing issue: [#646](https://github.com/realkarych/kora/issues/646), a bounded child of [#552](https://github.com/realkarych/kora/issues/552) within [#593](https://github.com/realkarych/kora/issues/593). Governing contracts: [IR sections 2.1, 7.1, 7.4 and 10](../specs/ir.md), ADR-0006/0018 and the published artifact views. This record describes static checker integration, not runtime approval or graph admission.

## Delivered boundary

The existing approval pass builds a closed input record from direct whole-output bindings to ordinary producers in the current graph/body. Producer output contracts supply types. Supported non-list outputs use the exact native roles, direct StructuredOutput and the command file role for a namespaced parent-null custom without inline overrides. Command file output requires the configured file and sole extra declaration. All supported types are ancestry roots, so matching producer/consumer names establishes the nominal prerequisite within this scope; this is not a replacement for general saved-ancestry assignability.

AgentSession uses the packaged frozen CEL schema with its own checker root. After all binding prerequisites, shared pure IR acquisition verifies both exact published resource extents and digests before decoding. The existing engine adapter retains its precharge and refusal mapping. The approval cache retains one mapped Variable or a fixed schema-unresolved status, including failed acquisition. The existing invocation-local schema mapper retains the verified checker schema until the call returns. StructuredOutput uses its accepted role-owned inline schema and structured-output view. Forms/parameters retain PLAIN mapping. The source module preserves complete Variable bounds, original local-reference bases, optional guards and selection-only inputs. No synthetic schema supplies an unavailable context.

Unknown source/output/revision, differing endpoint types, inherited customs, lists, paths, reserved sources, wrappers/collections and unsupported inline combinations remain context-unresolved. The accepted #669 declaration-only agent source is selected when the configured schema is absent. The both-present equality rule applies when both sources exist. All binding prerequisites precede schema mapping; malformed mapped schemas remain schema-unresolved. A missing or empty inputs map is a real closed empty record, so unknown names and forbidden root use reach ordinary typed diagnostics. Independent predicates continue.

Sources and producer-wide role decisions are cached within one invocation. Mapping success/failure is cached by schema-root/view identity, including shared malformed schemas across different producers; no exception or traceback is retained. Mapped types and nested bounds are shared rather than cloned. Each expression still prepares/checks its own environment, so schema reuse establishes no globally linear validation or wall-time guarantee.

## Threat and resource assessment

Existing TM-04 covers authored schemas/expressions and closed reference authority; TM-06/TM-07 cover content-free diagnostics and the AgentSession allowlist; TM-10 covers bounded checking and owned transient state; TM-11/TM-12 cover immutable packaged interpretation and evidence. No actor, credential, persistence, filesystem/network execution authority, runtime assumption or dependency changes. Schema resources are existing published data copied unchanged into the installed package, not downloaded at runtime. No threat-model policy amendment is needed.

The synchronous invocation owns source caches, selected views, schema mappings and generated input records/bounds. Individual environments/ASTs/check results are expression-local. The result owns only copied bounded diagnostics and scalar counts. Tests use real schema/checker components and exact ownership observations, not mocks, process-wide heap thresholds or an additional qualification campaign. No asynchronous resource owner is introduced.
