## Delivered ownership and dispatch

The [normative API contract](../specs/api-and-agent-surface.md#initial-asgi-application-issue-541) and real registration-derived catalog define exactly GET /healthz and GET /api/v1/openapi.json. The first is anonymous fixed status with no authentication/database work. The second checks the current configured personal principal, including empty grants, before all method refusals. Service tokens remain forbidden. Body-free HEAD, trusted Allow, API012/405, API013/501 and unknown-path API001/404 follow accepted #538; the fixed recognized-method set grants no extra handler. Public router matching preserves root-path behavior. Default docs/root-schema/OAuth/HEAD/OPTIONS/redirect helpers are absent.

Authorization names are counted case-insensitively from raw ASGI header pairs before selecting a sole Latin-1 value; preserving incoming header case cannot hide a duplicate. Schema authentication retains the ordinary RequestInfo freshness default and existing nonlocal-provider cache tolerance. Stronger current-authority checks remain with their specified stream/metrics operation owners.

The application borrows authenticator, clock, diagnostics and identity source. It configures no process logging, opens no database/listener, creates no body buffer, queue/pool or background service, and does not close those borrowed resources on lifespan shutdown. The per-request wrapper copies only standard HTTP scope entries, retains opaque state/extensions without authority, starts empty canonical logging and OpenTelemetry contexts, emits one current header identity and restores both contexts on every exit. Unexpected framework errors produce safe API010 before headers, retain one safe failure diagnostic and propagate the original exception. No JSON is appended after response-start failure. Accepted response status is recorded only after send returns.

This is an in-process ASGI boundary, not a listening server, socket/header parser, TLS/proxy/framing implementation, standalone deployment or domain API. The unused request body is not consumed; that supplies no general 4 MB ingress-limit claim. No graph/worker/token/mutation/replay/stream/readiness/metrics/upload or client/CLI/MCP/console capability is activated. Their existing implementing owners retain parity and durable-event gates.

## Telemetry source and import limits

Pinned [FastAPI application](https://github.com/fastapi/fastapi/blob/0.162.0/fastapi/applications.py), [telemetry API](https://github.com/fastapi/fastapi/blob/0.162.0/fastapi/telemetry/_api.py), [ASGI instrumentation](https://github.com/fastapi/fastapi/blob/0.162.0/fastapi/telemetry/_asgi.py) and [lifespan runtime](https://github.com/fastapi/fastapi/blob/0.162.0/fastapi/telemetry/_runtime.py) were inspected, together with installed pinned source. Context7 lookup failed, so these official sources supplied the fallback.

The factory explicitly sets tracing, metrics, logs, operation_spans and auto_configure false. This short-circuits native request signal-provider lookup and automatic exporter setup. It does not remove inherited native request metadata or ambient OpenTelemetry Context, so the owned boundary also projects standard HTTP scope fields and attaches/detaches a fresh empty public Context. Production uses no private FastAPI key or global provider setter.

The supported import environment leaves OTEL_PYTHON_CONTEXT and OTEL_PROPAGATORS unset, using default contextvars and built-in tracecontext/baggage propagators. Import-time plugin selection happens before constructor flags; the factory neither mutates environment nor sandboxes independent outer instrumentation. FastAPI lifespan can flush components previously owned by another instrumented application. This closure contains no SDK/exporter or such preexisting owned component; future listening/standalone composition must own broader import/global-component policy. No process-wide no-export or no-plugin-lookup guarantee is claimed.

`tests/api/test_telemetry.py` drives complete ASGI lifespan and requests in owned child processes under adverse native auto-export/provider selectors. A genuine public proxy tracer provider supplies outer native request telemetry; the owned inner wrapper removes inherited carriers, preserves every standard field and the caller mapping, and restores outer native context across success, failure and cancellation. No SDK, transport/provider double, global setter, private production access or behavior patch is used. A first provider-positive-control assertion incorrectly expected the missing selector value in exception prose; pinned source raises through the real provider loader without reflecting it. The existing sink limits and deadlines are preserved. These checks establish exact ownership and failure independence, not heap/RSS or timing guarantees.

`test_installed_api_application_uses_only_runtime_dependencies` installs the actual wheel and its locked runtime closure offline into a private environment. It reuses the existing distribution fixture and verified installed-payload wheelhouse; no new network, dependency or build path is introduced.

An initial context test attempted to inspect deliberately foreign logging keys through the canonical-context validator; it failed because that validator correctly rejects foreign keys. The corrected assertion reads the borrowed external structlog context directly and still checks exact object restoration and empty internal scope. Local lint/type setup findings were fixed without relaxing settings or assertions. ## Security, observability and verification limits

Existing TM-01/TM-02 cover bearer-only/current principal authority and protected dispatch; TM-06/TM-07 cover content-free errors, correlation, safe exception frames and telemetry exclusions; TM-10 covers no body buffering and actual request/DB/context/writer release; TM-12 covers exact dependency provenance and truthful activation evidence. No new actor, credential, protection claim or deployment assumption needs a human-validated threat-model amendment. All five telemetry flags and the two distinct inherited carriers remain separate review obligations.

The API activation row in [observability](../specs/observability.md#7-component-coverage-and-activation) owns DEBUG api.request.completed and ERROR api.request.failed. Only static route/unmatched, accepted status, fixed code and safe exception classifications are emitted; raw method/path/query/body/headers/credentials and exception prose/source/locals remain excluded. API factory lifespan never assumes sink ownership.
