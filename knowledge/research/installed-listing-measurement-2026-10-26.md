# Installed-provider listing measurement

## Preregistered method

Declared on 2026-10-26 before the first listing instrumented run, for issue #248. This is an initial implementation baseline, not a comparison with a nonexistent base command. The owner permits local shared-host execution; timings from that host are descriptive, not uncontended latency claims. No numerical latency or RSS regression threshold is invented. The gates are the accepted buffer bounds and affirmative release of owned resources.

Three independent long-lived parents run each of two installed datasets. Each parent performs ten warmups (success, failure, cancellation, shutdown, repeated twice, then success and failure), followed by thirty successes, ten failures, ten cancellations and ten shutdowns: seventy cycles per dataset and parent, 420 cycles altogether. Each cycle includes real acquisition, metadata execution and closure. Cancellation cancels the discovery task; shutdown closes its owning asyncio Runner while discovery is blocked. The parent process remains alive across cycles, including Runner replacement after shutdown. Decision time comes from an injected clock; process exit, reaping, identity absence and group emptiness are native observations.

The original small dataset contains the three installed core entries and one controlled external entry. The original high-count dataset contains the same three core entries and 253 external entries in one separately built distribution, using one shared metadata module. Every external schema is exactly 8,192 canonical UTF-8 bytes, depth one. The original high-count fixture schemas total 2,072,576 bytes, exceeding one result record. The final external factory provides a control barrier after preceding external metadata allocation. Failure replaces that factory's successful result with an ordinary loader failure; it adds no entry. Cancellation and shutdown interrupt the barrier. The ordinary wheel tests separately cover an exactly 1,048,576-byte schema and sustained raw output.

The instrumented parents use the locked editable core plus real fixture wheels in dedicated environments. An explicit study `.pth` selects the existing locked environment packages and editable core source; uv installs the actual fixture wheel with no index and no dependencies. This declared instrumentation environment is not the isolated ordinary-wheel proof. This is distinct from ordinary tests that build and install the complete kora wheel without its conformance extra. Retain source/lock hashes, Python/platform details, wheel hashes and sizes, setup commands, setup duration and complete qualification duration. No frontend setup is needed by this editable-core study.

Trace parent Python allocations from interpreter startup. Sample every 20 ms and at acquisition, metadata barrier, result retention, closure and settled checkpoints. Record current/peak Python bytes, current native RSS, native high-water RSS, Python/native threads, tasks, active timers, selector watches, imported modules and descriptors by kind. Observe active child RSS and native threads; record departed counter reads rather than replacing unavailable observations with zero. Sampled native peaks are lower bounds. Retain all points and allocation snapshots/differences every ten cycles, including the twenty largest final allocation differences.

Repeated child tracing starts in the fixture module after its dependencies import and excludes those dependency imports and earlier core imports. Record current/peak Python bytes and imports at the control barrier, and after normal child completion before interpreter teardown. Terminated children have a barrier counter but no final Python counter; the final counter is explicitly unavailable. A separate cold leg starts `-I -X tracemalloc=1` before interpreter imports and invokes the unchanged installed child through an installed wrapper with the same real result/event channels. Keep its startup-inclusive current/peak, imports and native observations separate from fixture-phase counters and identify wrapper overhead.

After dropping result, task, exception and schema references and collecting garbage, require weakly referenced invocation/process/result owners to be collected, no retained matching process identities or members, reaped direct children, no private listing roots, and exact warmed descriptor/task/timer/watch/thread/import counts. Save a nonempty process registration before release; an unknown observation never counts as absence. Record snapshots after every ten cycles to distinguish live retainers from allocator high-water retention. The bounded seventy-cycle evidence list remains intentionally retained by the measurement parent and is identified separately in allocation analysis. Successful and failed metadata results retain their expected provider/failure counts before disposal.

Separately exercise 1,100 offered registry events, blocked and broken parent diagnostic sinks, and actual command exit. Offered volume alone does not prove queue saturation; report observed loss/queue counters and complete-delivery versus refused-incomplete results accurately. Synchronous private-directory setup/removal/evidence operations have no hard interruption guarantee for arbitrary filesystem stalls; the fourteen-second listing phases govern process/group/channel closure.

The existing 240-cycle foundation study and collector remain unchanged. Listing writes a separate sidecar and raw artifacts within the existing qualification output directory, and is invoked by the existing qualification test module. No workflow topology, coverage, timeout or ten-minute budget changes. Record total qualification time; a capacity failure must be fixed without silently reducing either population.

CI shard amendment, 2026-10-28, [approved explicitly by the project owner](https://github.com/realkarych/kora/pull/379#issuecomment-6468762431): that capacity failure occurred on hosted runners. The [hosted measurement shards](conformance-lifetime-measurement-2026-10-23.md#hosted-measurement-shards-2026-10-28) run listing as its own nightly job and pytest process with an unchanged population, so its cutoff no longer includes foundation time and its sidecar `seconds` and `remaining_qualification_seconds` refer to that shard alone. Total qualification time is recorded by the per-measurement sidecar time and the workflow run's duration from the first shard's start to the join's completion.

## Registry diagnostic routing correction

Native review of PR #277 found that an ordinary library warning became a non-registry diagnostic on the registry channel and refused an otherwise valid discovery. An installed warning fixture reproduced the failure in both schema modes. The child now drains its structured diagnostics through a bounded local relay, discarding non-registry records before forwarding registry records unchanged to the parent's strict validator. The relay owns one socket pair and one worker inside the already parent-owned child; parent discovery and cleanup deadlines are unchanged. The ordinary target set passed 61 cases after the routing correction. The ac713f7 measurements above predate this producer change; fresh listing evidence is recorded separately in PR #277, while unchanged foundation evidence is reusable. No earlier numerical observation is presented as a measurement of the corrected relay.

## Probe timer-barrier correction

CI at 77afea9 passed both Linux lanes but one macOS TERM-resistant cancellation probe reached its twelve-second timeout. The old bytes assertion truncated the subprocess traceback, so that run does not identify the waiting phase. Complete fixed-phase, timer and task diagnostics now survive test failure. Twenty serial and sixty concurrent local attempts did not reproduce that CI failure; they do not explain it.

A separate deterministic real-child case exposed a terminal-state defect in the probe: after the cancelled discovery had already released its owned process, the probe waited for a cleanup timer that would never be created. The regression failed with an empty timer set and a completed cancelled operation. The corrected barrier also waits for operation completion and joins its temporary waiter, then retains all outcome, native identity, group, descriptor and task assertions. TERM-resistant cases additionally require a SIGKILL exit status. Discovery-timeout and repeated-cancellation cases must still reach their named phase. Product and test deadlines are unchanged. These ordinary-probe changes do not change the listing or foundation measurement producer; PR #277 records final execution evidence and the original CI limitation separately.

The diagnostic revision also exposed an initial-peer wait after discovery had completed on Linux/Python 3.15. Peer acceptance now races discovery completion and propagates its original failure. The accept task is joined and any accepted socket remains owned by probe cleanup. That run did not retain the completed operation's exception; no production cause is inferred from the terminal state alone.

## Probe timeout ownership and transport preparation

CI at 610007a failed the macOS descendant probe's outer twenty-second guard with no traceback. Inspection found another deterministic cancellation cycle: the probe's twelve-second timeout cancelled its direct await of discovery, which correctly deferred cancellation until cleanup; cleanup awaited a frozen decision clock that the probe restored only in its unreachable finalizer. The probe now waits for task completion without forwarding cancellation, outside the handler that classifies the discovery result. An immediate-timeout case with a real TERM-resistant child reproduced the old twenty-second hang. After correction, all thirteen installed lifecycle cases passed, retaining exact SIGKILL, reaping, identity, group, descriptor and task assertions. This repairs the demonstrated cancellation cycle without claiming to identify the native condition that first delayed the original descendant case.

The same CI run failed the Linux/Python 3.11 transport EOF and terminal cases at their five-second frontier. All process and tree records were already closed; a final journal-publication helper remained owned. The complete cases took 8.814 and 8.726 seconds including preparation and failure disposal. A separate Linux x86 CPython 3.11.17 observation recorded 23 sequential real helpers, each taking approximately 0.24–0.31 seconds and reaching native exit. The existing frontier included client reservation, acquisition, replay, acknowledgement and observation before closure.

Those cooperative transport cases now acknowledge an explicit preparation barrier before the child requests close. The existing five-second guard starts before releasing that barrier; the unchanged ten-second whole-test guard still covers preparation and closure. The idle handshake and every resource assertion remain, as do the header and cancellation cases. This corrects the Arrange/Act boundary; it does not establish that the earlier combined setup-and-close workload passed its five-second guard. No production deadline, CI topology or timeout value changes. PR #277 records the affected platform checks and independent assessment; historical failed runs retain their verdicts.
