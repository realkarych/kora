Checked: 2026-10-20, for [issue #155](https://github.com/realkarych/kora/issues/155), against the configuration of that change on top of `master` at `6b784b7`, with Ruff 0.17.1, Pyright 1.1.414, pytest 9.1.1, ESLint 10.13.0 and typescript-eslint 8.71.2 from the lock files. This record carries the rule families selected to enforce the "no suppression" rules of [AGENTS.md](../../AGENTS.md#code), every configuration allowance with its reason, the probes that show what each tool catches and misses, and the residuals that stay review items. The decisions are the owner's approval of the implementation plan on the issue; nothing here is a decision. The [logging and scanner record](logging-stack-and-ci-scanners-2026-10-20.md) carries the `S` family and the scanners; this record is the current list of every Ruff allowance.

Four settings accompany the families. `ruff check` runs with `--ignore-noqa` in CI and in the development instructions, so a `# noqa` comment suppresses nothing even before the repository test reports it. `[tool.ruff] respect-gitignore = false`: with the default, one line in `.gitignore` or `.ignore` hides a tracked file from Ruff and with it from every Ruff-only rule (probe: a tracked test module carrying `pytest.mark.skip`, then its path added to `.gitignore`, passed `ruff check --ignore-noqa .`). `[tool.ruff] extend-exclude = [".claude"]`: with `respect-gitignore = false` Ruff no longer honours the host's `.git/info/exclude` entry for `.claude/worktrees/`, so without the exclusion the root `ruff check .` on a developer machine would also lint those nested worktrees, each under its own configuration; the directory holds no tracked source and CI checkouts have none. `[tool.pytest.ini_options] empty_parameter_set_mark = "fail_at_collect"`: with the default, `@pytest.mark.parametrize("x", [])` reports the test as skipped and the run exits 0.

Both filters existed before this change: the expression-index filter in `tests/db/test_migrations.py` and `tests/db/test_log_filtering_does_not_change_durable_events.py`, the `always` filter in `tests/observability/test_logging_redacts_content_and_safe_exception_chains.py` |

The blind-handler count follows Ruff's `BLE001`: a handler re-raises when a `raise` statement in its body, outside nested `try` statements, functions, lambdas and classes, is bare or names the caught exception as the exception or as the `from` cause (`raise Wrapped() from error` re-raises; `raise Wrapped()` does not; a `raise` inside a nested `except` or a nested function does not count). The count is stricter than Ruff in two places: a bare `except:` counts (Ruff leaves it to `E722`, which is selected) and a handler that only logs the exception counts (Ruff exempts `logging.exception`; AGENTS.md forbids log-and-continue).

The two `except Exception` handlers that the holder coroutines of `tests/db/test_transactions.py` and `tests/observability/test_db_diagnostics_follow_the_commit.py` carried were removed, not allowed: with the real fixture on both databases, the held unit returns without an exception after `Database.close(deadline_seconds=0.2)`, so the handlers never ran and a future exception should fail the test. On SQLite the write of that held unit is lost: `StaticPool.dispose()` closes the single pooled connection while it is checked out, and SQLAlchemy's aiosqlite adapter skips `commit` once the aiosqlite connection is closed, so the unit reports success and the row is gone; on PostgreSQL the row persists. That is a pre-existing `kora.db` defect on `master`, outside this change, recorded here for the follow-up issue; `test_close_after_the_deadline_fails_the_unit_and_releases` asserts nothing about the fate of the write. [Issue #158](https://github.com/realkarych/kora/issues/158) fixed it: a unit that outlives the close deadline now raises `DatabaseClosedError` and writes nothing on both databases, and `test_close_after_the_deadline_fails_every_unit_in_flight_and_writes_nothing` replaces that test.

## Repository test

`tests/architecture/test_no_suppression.py` walks the repository from its root, skipping dotted directories, `__pycache__`, `node_modules`, `measurements`, `dist`, `build`, `web/dist`, `web/build`, `web/node_modules` and `src/kora/api/static`, symbolic links, and the listed generated files (`uv.lock`, `web/pnpm-lock.yaml`; the test asserts they exist, so the list cannot rot; the generated TypeScript client enters it, and the ESLint `ignores`, in the change that generates it). Files are read as UTF-8 with an optional byte order mark. Python and `.pyi` files, and extensionless files whose shebang names `python` (directly or through `env`, interpreter options skipped), go through `ast` first (a file that does not parse fails the test with its name) and then `tokenize` (every comment token except a line-1 shebang is a comment or, when it matches the directive patterns, a tool directive; string contents never match) and the `ast` checks: every bare string statement, `monkeypatch` and `mocker` parameters, `add_marker`/`applymarker` with a string constant or a constant-only f-string, `skipTest` calls, `addinivalue_line`, any `pluginmanager` attribute under `tests/`, `catch_warnings` with an `action` keyword outside the helper, `__import__`/`import_module`/`resolve_name` whose target or `package` argument names `pytest`, `_pytest`, `warnings` or `unittest` (dotted or colon syntax), `sys.modules[...]` subscripts and `sys.modules.get(...)` calls naming those modules, `getattr(..., "skip")` and the other banned attribute names as string constants, blind handlers in any file without a pinned count and a pinned file whose count differs from its pin, and in every Python file any module-scope binding (function, class, assignment including tuple targets, `for` and `with` targets, aliased import or `from` import, a walrus or `match` capture pattern anywhere in a module-scope statement's expressions including `with` items, parameter defaults, class keywords, `match` patterns and guards, `except` clauses and comprehensions, and a `global` declaration anywhere in the file, also inside module-level `if`, `try`, `with`, `for`, `while` and `match` blocks) named `pytest_*` beyond `pytest_report_header` and `pytest_generate_tests` in `tests/conftest.py`, plus the variables `collect_ignore`, `collect_ignore_glob` and `pytest_plugins` anywhere (pytest loads `pytest_plugins` from test modules too). The allowance file `tests/support/warning_filters.py` is pinned by its content digest, which is the decisive pin, and by the structural rules on its imports, module-level definitions, `warnings.*` names, pattern constant and filter-call arguments, which state what the digest protects. Shell (`.sh`, `.bash`, `.zsh`, `.ksh` and extensionless files with a shell shebang), SQL (`.sql`, `.psql`, `.pgsql`) and the Alembic template (`.mako`, where `#`, `##` and `<%doc>` all count) report every comment after quoted strings are removed; TypeScript and JavaScript (`.ts`, `.tsx`, `.mts`, `.cts`, `.js`, `.jsx`, `.mjs`, `.cjs`) report directives only, because ESLint owns their comment ban. The configuration check compares the whole `[tool.ruff]`, `[tool.pyright]` and `[tool.pytest.ini_options]` tables, the three `web/tsconfig*.json` documents and the `scripts` table of `web/package.json` with recorded values, states the invariants in words (every `filterwarnings` entry is `error`, `--strict-config` and `--strict-markers` present, `ignore` empty, `typeCheckingMode` strict, `enableTypeIgnoreComments` false, `compilerOptions.strict` true), refuses `pytest.ini`, `.pytest.ini`, `tox.ini`, `setup.cfg`, `pyrightconfig.json`, `ruff.toml`, `.ruff.toml` and a second `pyproject.toml` anywhere in the scanned tree and any `eslint.config.*` or `.eslintrc*` anywhere other than `web/eslint.config.mjs` (ESLint looks configuration up from each file's directory to the filesystem root and prefers `eslint.config.js`; ESLint 10 never reads `.eslintrc*`, so that refusal is defence in depth), requires `web/eslint.config.mjs`, the listed generated files and the allowance file to exist, and refuses a `[project.entry-points.pytest11]` table. The tree check runs in well under a second.

Directive patterns, case-insensitive and whitespace-tolerant: `noqa`, `type: ignore`, `pyright:` (every Pyright comment), `pragma:`, `fmt:`, `ruff:`, `isort:`, `mypy:`, `pylint:`, `flake8:`, `coverage:`, `nosec`, `eslint-disable`, `eslint-enable`, `eslint-env`, `@ts-ignore`, `@ts-expect-error`, `@ts-nocheck`, `@ts-check`, `prettier-ignore`, `biome-ignore`.

## ESLint

`web/eslint.config.mjs` defines the plugin object `kora` with the rule `no-comments`, which reports every comment token except a shebang and applies to every linted file (`eslint.config.mjs`, `vite.config.ts` and, through an explicit `files` entry with JSX parsing, `.jsx` files, which ESLint would otherwise not lint at all); `globalIgnores(["dist/"])` keeps a local build output out of the lint; `linterOptions.noInlineConfig = true` makes every inline `eslint-disable`, `eslint-env` and `global` comment ineffective and reported as a warning, which `--max-warnings 0` turns into a failure; `linterOptions.reportUnusedDisableDirectives = "error"` is inert while `noInlineConfig` is on (the linter builds no directive list) and is the layer that remains if it is ever turned off; `@typescript-eslint/ban-ts-comment` bans `@ts-check`, `@ts-expect-error`, `@ts-ignore` and `@ts-nocheck` (the strict preset allows `@ts-expect-error` with a description). Probe on the installed ESLint, a scratch `src/Probe.tsx` with a plain comment, an `eslint-disable-next-line` and a `@ts-expect-error`: five errors (three `kora/no-comments`, one `@typescript-eslint/no-unused-vars` the directive had tried to hide, one `ban-ts-comment`) and one `noInlineConfig` warning, exit 1; a scratch `src/Probe.jsx` with a line comment and a JSX comment: two `kora/no-comments` errors; the tree passes. No dependency was added: `@eslint-community/eslint-plugin-eslint-comments` would duplicate what the local rule and `noInlineConfig` give.

## Limits of this record

The probes show what the pinned tool versions catch on 2026-10-20; a Ruff, Pyright, pytest or ESLint upgrade can change a row and is checked by rerunning `tests/architecture` and the probes. A green check is not proof that every rule of AGENTS.md is met; the rules apply to every form, including the ones above.
