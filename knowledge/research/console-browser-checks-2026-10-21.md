# Console browser checks

## Current console-functional-v1 protocol

The owner approved [complete removal of the experimental numerical browser benchmark](https://github.com/realkarych/kora/issues/179#issuecomment-6329273349) on 2026-10-22. The earlier v4 training/holdout procedure is retired. No further empirical threshold, training series or numerical browser regression promise is active. Historical failed attempts retain their verdicts and unresolved causes; removing the benchmark does not establish leak freedom. The compact inventory below links the complete retired procedures and observations.

`pnpm --dir web run test:browser` builds the current production assets and drives real production/development servers at 1280, 768 and 375 pixels. Every viewport navigates and reloads, waits for visible heading, fonts, complete document and first contentful paint, then checks semantics, keyboard focus and overflow with zero unexpected diagnostics. Screenshots, terminal screenshots and bounded traces remain. `--smoke` is a compatibility alias for this same suite. Actual child CLI checks reject removed, unknown and duplicate modes before acquiring directories or processes and verify argument-marker exclusion from output.

Six failure cases cover startup, navigation, assertion, deadline, cancellation and acquisition cancellation. Ordinary and report-collision cancellation verify exact descendant release and empty temporary contents before fallback; a forced/stalled runner exercises bounded parent cleanup. Linux retains exact owned PIDs, descriptor/process release observations and native resource evidence; unavailable native counters on macOS remain unverified. HTTP/WebSocket exact-origin routing, a pinned-destination proxy, service-worker blocking, sanitized child environments, proxy/socket release and the real network-denial fixtures remain. These controls concern cooperative contributor tooling under TM-12, not hostile-code containment or a product firewall.

Artifacts remain bounded to 32 MiB per file and 512 MiB cumulative, reserving the final report. The report binds checkout/head/dirty state, locked browser tools/distribution and asset hashes to the retained checks. Diagnostics use bounded browser capture and fixed content-free failure classes. Numerical base/head builds, trial persistence/finalization, GC, heap snapshots, loading/memory/RSS statistics, budgets and calibration/holdout commands are deleted. Functional resource release remains exact; backend/CEL/database measurement requirements are unchanged.

CI now has exactly one `Console browser checks` job, invokes the ordinary command and uploads `console-browser-checks`. There is no slot matrix, comparison base or calibration environment. Pinned actions/tools, read-only permissions, other CI jobs and hard execution/cleanup deadlines remain. Whole-workflow duration follows the existing ten-minute feedback target in the [accepted MVP amendment](bounded-mvp-verification-2026-10-29.md). Full automated accessibility scanning remains unverified and API-backed journeys activate with their implementing components.

### Functional evidence and trust boundaries

Playwright remains a development-only dependency pinned with its matching core package and integrity hashes in the [frontend lock](../../web/pnpm-lock.yaml). Reports bind the locked automation, browser distribution and asset identities; npm lock integrity does not itself authenticate browser archives. Fresh profiles, contexts and output directories use loopback servers and local synthetic shell content. HTTP/WebSocket controls do not provide an OS sandbox, WebRTC containment or a general firewall for installed code.

[Browser capture](../../web/tests/browser/page.ts) retains at most 100 records of 512 characters, and [child capture](../../web/tests/browser/ownership.ts) is limited to 64 KiB. [Artifact admission](../../web/tests/browser/artifacts.ts) watches the 32 MiB per-file and 512 MiB cumulative limits; these are detection thresholds, not instantaneous filesystem quotas. Finalization reserves 4 MiB for the report and 64 KiB for a bounded truncation marker. Overflow/truncation fails the run, retains bounded marked failure evidence and never produces a valid oversized trace. [Smoke traces](../../web/tests/browser/smoke.ts) omit source files, DOM snapshots and embedded screenshots; separate viewport screenshots retain failure evidence.

CI uses read-only permissions, pinned actions/tools and checkout without persisted credentials, with no explicit secrets or OIDC token. Uploaded artifacts are evidence only and must not be consumed by a privileged workflow. A workflow file alone does not activate merge protection; required-status configuration remains an owner-controlled repository setting. The [development guide](../../docs/development.md#browser-checks), [active verification checklist](../reviews/ai-development-setup.md#browser-benchmark-exclusion) and [current workflow](../../.github/workflows/ci.yml) retain current commands and acceptance.

### Complete pre-close ownership admission

On 2026-10-29 the owner explicitly approved [the revised plan in issue #411](https://github.com/realkarych/kora/issues/411#issuecomment-6489535303), with [approval recorded separately](https://github.com/realkarych/kora/issues/411#issuecomment-6489739697). This replaces immediate refusal of a Linux pre-close `EACCES`/`EPERM` with one finite opportunity to obtain a complete fresh strict snapshot. It changes a verification admission condition, not application behavior or a product security guarantee.

Ownership first joins its already-started acquisitions with their existing fifteen-second launch/connect allowances. It then establishes one absolute five-second deadline shared by pre-close discovery and browser/server closure. Only Linux permission denial permits another fully awaited strict observation, separated by an event-loop yield. The first actual denial object remains the failure if admission cannot complete; unrelated errors fail immediately. No failed observation supplies PIDs or counters. A successful snapshot must arrive before the deadline and include every initially-live root, whose original ChildProcess handles are checked before and after observation and immediately before adding discovered PIDs. Unexpected root exit refuses admission. Roots already exited before discovery remain compatible with startup/navigation failure cleanup.

Browser/server close timers receive that same absolute deadline and use only its remaining allowance; an exhausted allowance invokes forced termination immediately. They never receive a fresh five seconds after discovery. The separate five-second release waiter, final strict counters, proxy/socket assertions, forced-cleanup refusal and temporary-removal conditions remain. Later zero counters cannot erase an admission failure. Generic collection still immediately rejects an unreadable live process, and its disappearance/zombie rules are unchanged.

The real nondumpable-child fixture now has an explicit restore/ack control that leaves it alive. Resource and actual Ownership probes cover restored complete inventory before separate termination, persistent denial with first-error preservation, initially-live root loss, rejection of a late complete snapshot and the delegated absolute close target. All original release cases remain. The ordinary browser suite retains every production/development viewport, six failure cases, cancellation, network restriction and artifact bound. No numerical benchmark, dependency, workflow or supported platform changes.

This is an admission deadline, not a five-second completion guarantee for blocked kernel I/O. Each observation settles before another begins; none is abandoned. Parent fallback itself awaits discovery before signalling, and top-level smoke has no separate thirty-second fixture parent. These existing limitations and the ten-minute job cutoff remain. Native counters unavailable on macOS remain unverified. The change affects cooperative contributor ownership evidence under TM-12 and grants no execution or network authority.
