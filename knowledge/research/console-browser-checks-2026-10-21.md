# Console browser checks

Checked on 2026-10-21 under [issue #179](https://github.com/realkarych/kora/issues/179). The owner approved the [implementation plan](https://github.com/realkarych/kora/issues/179#issuecomment-6320728472). This record distinguishes the calibration protocol from completed measurements; no reference baseline is claimed before its artifact exists.

## Dependency and execution boundary

Playwright 1.64.1 is a development-only dependency, pinned through pnpm with its matching core package and integrity hashes. It drives real Chromium, traces and browser resource counters; the standard library cannot supply browser automation. No application dependency or API contract changes. The package metadata selects Chromium revision 1248, Chrome for Testing 156.0.8078.4. Installation uses the Playwright distribution CDN; the lock hashes the npm packages, not the downloaded browser archive. Runtime version and distribution metadata are recorded in every report. The [Playwright source](https://github.com/microsoft/playwright/tree/v1.64.1) defines the automation and distribution behavior.

The CI job uses `pull_request`, `contents: read`, full action pins and checkout without persisted credentials. It receives no explicit secrets, write permission or OIDC token. Uploaded artifacts are evidence only and must not be consumed by a privileged workflow. Required-status activation is a separate owner action; a workflow file alone does not configure merge protection.

A fresh profile and context run against loopback-only servers. An exact-origin HTTP proxy also governs redirect destinations and WebSocket tunnels. Playwright request routing rejects initial foreign requests, service workers are blocked, and WebSockets are routed before page creation. Routing alone is insufficient because Playwright handles only the first URL in a redirect chain. Real local negative cases check an alternate loopback origin, redirects, WebSockets, CONNECT and service-worker registration. This is an HTTP/WebSocket test boundary, not an OS sandbox for PR code or a general network firewall; WebRTC and arbitrary installed code require separate containment.

Diagnostics retain at most 100 records of 512 characters; child output is limited to 64 KiB. Reports are limited to 4 MiB, heap snapshots to 32 MiB each, and an artifact-directory watcher terminates owned work on a 32 MiB file or 512 MiB directory limit. Oversized files are retained as truncated failure evidence with a marker, never treated as valid traces. Traces omit source files, DOM snapshots and embedded screenshots; separate viewport screenshots cover first failure. Only local synthetic shell content is used. Each invocation creates a new output directory so calibration, failures and final verification cannot overwrite each other.

## Preregistered measurement protocol

The same head harness and production build configuration drive base and head. The base is the explicit forty-character Git revision in `KORA_BROWSER_BASE`; the checked-out revision and PR head are recorded separately. Base tracked web files are copied into an owned temporary directory and built using the same locked head toolchain, Vite configuration and dependency tree. Asset SHA-256 values are retained. No live API/database/scheduler exists behind this static shell, so their journeys remain pending their implementing issues.

One complete comparison has three independent browser-process pairs, run serially on an uncontended Linux x86_64 reference runner. Calibration order is base/head, head/base, base/head; verification reverses that order. Every process has two warm-up and twenty measured cold-context loads, then three warm-up and thirty measured reload cycles in one long-lived page. Each lifecycle cycle also creates, loads and closes an additional context. All warm-up and measured samples remain in the artifact. Viewport is 1280 by 900, no network or CPU throttling, fresh contexts for cold loads; routing disables the HTTP cache for both arms. Production and development smoke at widths 1280, 768 and 375 plus real failure-path checks run outside the measurement window.

Readiness requires the visible heading, ready fonts, FCP and LCP. There is no fixed sleep or network-idle synchronization. Each process reports loading median/p95, transfer bytes, CLS and long tasks. The independent statistical unit is the process pair, not individual loads; all three paired differences and between-process spans are retained. Three pairs support an empirical regression check, not strong population-level confidence or field INP claims.

Lifecycle samples retain natural pre-GC and post-GC heap, documents, DOM nodes and listeners, process-tree RSS/descriptors/processes, runner memory and context/page counts. Baseline/end heap snapshots support retaining-path analysis. Full spans, late spans over cycles 16–30, first-ten versus last-ten medians and sampled peaks are reported. Explicit context release and terminal child exit are required; Linux `/proc` counters are unavailable on macOS and are reported as unverified there. Resource ownership includes browser children, server children, proxy sockets, IPC and capture pipes, temporary profiles/workspaces and bounded report arrays. Failure workloads cover occupied-port startup, real navigation failure, assertion failure, deadline and cancellation with an explicit ready signal.

Before calibration, the budget formula is fixed in `web/tests/browser/protocol.ts`. For each metric, take the maximum of the three **base** process summaries and add a margin equal to the maximum of twice their span, twenty percent of their maximum, and the resolution floor. Floors are 2 ms for load, 4 ms for FCP/LCP, 16 KiB for heap growth, 16 MiB for native RSS growth and 0.1 seconds for cleanup. Counts, CLS, long tasks and transferred bytes have zero resolution floor; their limits still derive from measured base values and variability, not an assumed zero baseline. A paired regression fails when its median exceeds the frozen margin or any pair exceeds twice that margin. Absolute gates apply to both base and head, so a shared defect cannot pass merely through equal behavior. The historical limits never replace the controlled comparison.

Calibration writes proposed budgets without claiming final verification. Freeze them only after checking valid workload completion, resource ownership and any unexplained retaining paths. A separate complete run verifies the committed limits. Missing paint/counters, unexpected traffic/diagnostics, revision or environment mismatch, incomplete samples or unsuccessful cleanup invalidate the comparison. Preserve failures and the cause of any replacement run; never select favorable samples or rerun unchanged until green. Budget increases require owner approval.

## Activation and evidence

The local command is `pnpm --dir web run test:browser`; `--smoke` is a supplemental functional-only run and never satisfies performance. Install the exact browser first with `pnpm --dir web exec playwright install chromium` (CI additionally installs system dependencies). `--calibrate` is the initial reference measurement mode, not a substitute for final gating. The parallel `Console browser checks` job retains every report and trace under `console-browser-checks` while preserving the existing CI jobs and ten-minute whole-pipeline limit.

At this revision, local source checks and smoke are being completed; Linux calibration, frozen budgets, final measurements, independent readiness reviews and full CI timing remain pending. The visible React shell is unchanged; no API mutation, authentication or fake backend journey is added.
