# Console browser checks

Checked on 2026-10-21 under [issue #179](https://github.com/realkarych/kora/issues/179). The owner approved the [implementation plan](https://github.com/realkarych/kora/issues/179#issuecomment-6320728472). This record distinguishes the calibration protocol from completed measurements; no reference baseline is claimed before its artifact exists.

## Dependency and execution boundary

Playwright 1.64.1 is a development-only dependency, pinned through pnpm with its matching core package and integrity hashes. It drives real Chromium, traces and browser resource counters; the standard library cannot supply browser automation. No application dependency or API contract changes. The package metadata selects Chromium revision 1248, Chrome for Testing 156.0.8078.4. Installation uses the Playwright distribution CDN; the lock hashes the npm packages, not the downloaded browser archive. Runtime version and distribution metadata are recorded in every report. The [Playwright source](https://github.com/microsoft/playwright/tree/v1.64.1) defines the automation and distribution behavior.

The CI job uses `pull_request`, `contents: read`, full action pins and checkout without persisted credentials. It receives no explicit secrets, write permission or OIDC token. Uploaded artifacts are evidence only and must not be consumed by a privileged workflow. Required-status activation is a separate owner action; a workflow file alone does not configure merge protection.

A fresh profile and context run against loopback-only servers. An exact-origin HTTP proxy also governs redirect destinations and WebSocket tunnels. Playwright request routing rejects initial foreign requests, service workers are blocked, and WebSockets are routed before page creation. Routing alone is insufficient because Playwright handles only the first URL in a redirect chain. Real local negative cases check an alternate loopback origin, redirects, WebSockets, CONNECT and service-worker registration. This is an HTTP/WebSocket test boundary, not an OS sandbox for PR code or a general network firewall; WebRTC and arbitrary installed code require separate containment.

Diagnostics retain at most 100 records of 512 characters; child output is limited to 64 KiB. Reports are limited to 4 MiB, heap snapshots to 32 MiB each, and an artifact-directory watcher requests termination when a file exceeds 32 MiB or the directory exceeds 512 MiB. These are detection thresholds, not instantaneous filesystem quotas. Finalization reserves 4 MiB for the final report and 64 KiB for a bounded truncation manifest; any truncation fails the run, including the reserve-boundary case. Finalization truncates overflow evidence within both bounds and records a marker; real file/directory overflow fixtures verify cleanup and retained limits. Oversized files are retained as truncated failure evidence with a marker, never treated as valid traces. Traces omit source files, DOM snapshots and embedded screenshots; separate viewport screenshots cover first failure. Only local synthetic shell content is used. Each invocation creates a new output directory so calibration, failures and final verification cannot overwrite each other.

## Preregistered measurement protocol

The same head harness and production build configuration drive base and head. The base is the explicit forty-character Git revision in `KORA_BROWSER_BASE`; the checked-out revision and PR head are recorded separately. Base tracked web files are copied into an owned temporary directory and built using the same locked head toolchain, Vite configuration and dependency tree. Asset SHA-256 values are retained. No live API/database/scheduler exists behind this static shell, so their journeys remain pending their implementing issues.

One complete comparison has three independent browser-process pairs, run serially on an uncontended Linux x86_64 reference runner. Calibration order is base/head, head/base, base/head; verification reverses that order. Every process has two warm-up and twenty measured cold-context loads, then three warm-up and thirty measured reload cycles in one long-lived page. Each lifecycle cycle also creates, loads and closes an additional context. All warm-up and measured samples remain in the artifact. Viewport is 1280 by 900, no network or CPU throttling, fresh contexts for cold loads; routing disables the HTTP cache for both arms. Production and development smoke at widths 1280, 768 and 375 plus real failure-path checks run outside the measurement window.

Readiness requires the visible heading, ready fonts, FCP and LCP. There is no fixed sleep or network-idle synchronization. Each process reports loading median/p95, transfer bytes, CLS and long tasks. The independent statistical unit is the process pair, not individual loads; all three paired differences and between-process spans are retained. Three pairs support an empirical regression check, not strong population-level confidence or field INP claims.

Lifecycle samples retain natural pre-GC and post-GC heap, documents, DOM nodes and listeners, whole-runner process-tree RSS/descriptors/processes, runner memory and context/page counts. Linux ownership discovery includes the children of every thread. Native checkpoints cover before/after server and browser acquisition, every completed cold load, each simultaneous-context workload, before GC, after GC and terminal release. These phase samples report observed peaks, not continuously sampled maxima; short transients between checkpoints remain unobserved. Counter collection occurs after the loading timing observation and uses identical checkpoints in both arms. Baseline/end heap snapshots support retaining-path analysis. Full spans, late spans over cycles 16–30, first-ten versus last-ten medians and sampled peaks are reported. Runner heap/external/ArrayBuffer spans and late growth, aggregate native spans and sampled peaks are gated by the same measured-base formula. Serialized evidence size is recorded to distinguish the intentionally bounded sample arrays from live resource ownership. Proxy socket counts must return to zero; runner descriptor/process counts must return to their pre-trial baseline. Explicit context release and terminal child exit are required; Linux RSS/descriptor counters are unavailable on macOS and are reported as unverified there; macOS terminal process release is checked using the POSIX process table. Resource ownership includes browser children, server children, proxy sockets, IPC and capture pipes, temporary profiles/workspaces and bounded report arrays. Failure workloads cover occupied-port startup, real navigation failure, assertion failure, deadline, cancellation with an explicit ready signal, cancellation during pending browser acquisition, and forced cleanup after stopping the actual runner process. Smoke screenshots and trace finalization run independently so one missing artifact cannot suppress the other or replace the primary failure.

Before calibration, the budget formula is fixed in `web/tests/browser/protocol.ts`. For each metric, take the maximum of the three **base** process summaries and add a margin equal to the maximum of twice their span, twenty percent of their maximum, and zero. No arbitrary byte or time floor is added. Every limit derives from measured base values and variability, not an assumed zero baseline. Proposed floors in the first source revision were withdrawn before any completed calibration: 16 KiB and 16 MiB are not the counters' resolution and had no measured justification. A paired regression fails when its median exceeds the frozen margin or any pair exceeds twice that margin. Absolute gates apply to both base and head, so a shared defect cannot pass merely through equal behavior. The historical limits never replace the controlled comparison.

Calibration writes proposed budgets without claiming final verification. Freeze them only after checking valid workload completion, resource ownership and any unexplained retaining paths. A separate complete run verifies the committed limits. Missing paint/counters, unexpected traffic/diagnostics, revision or environment mismatch, incomplete samples or unsuccessful cleanup invalidate the comparison. Preserve failures and the cause of any replacement run; never select favorable samples or rerun unchanged until green. Budget increases require owner approval.

## Activation and evidence

The local command is `pnpm --dir web run test:browser`; `--smoke` is a supplemental functional-only run and never satisfies performance. Install the exact browser first with `pnpm --dir web exec playwright install chromium` (CI additionally installs system dependencies). `--calibrate` is the initial reference measurement mode, not a substitute for final gating. The parallel `Console browser checks` job retains every report and trace under `console-browser-checks` while preserving the existing CI jobs and ten-minute whole-pipeline limit.

At this revision, local source checks and smoke are being completed; Linux calibration, frozen budgets, final measurements, independent readiness reviews and full CI timing remain pending. The visible React shell is unchanged; no API mutation, authentication or fake backend journey is added.

## First Linux attempt

[Run 39640184514](https://github.com/realkarych/kora/actions/runs/39640184514) on head `e577b3eacc5289d6334b6bef93befcd541e91bc2` stopped during the cancellation fixture before measuring base/head. Playwright's default process signal handler closed Chromium before the runner's explicit cleanup, which returned an error despite no remaining processes. No calibration was obtained. The subsequent implementation disables Playwright's signal handlers and keeps termination under the runner's owner, tracks pending acquisition, enumerates children of every Linux task, and includes runner/proxy resources plus active-context native checkpoints. The original failed artifact remains evidence, never a baseline or final pass.

Local smoke after the ownership changes passed at `/tmp/kora-179-smoke-15`. An earlier forced-cancellation experiment (`/tmp/kora-179-smoke-14`) failed with `EPERM` while signalling duplicated process identifiers; no surviving owned processes were found. The revised fallback deduplicates identifiers, preserves the ownership list before signalling, and checks actual macOS process liveness instead of returning stale roots. This local pass is supplemental; Linux calibration and final committed-revision review remain required.

The forced-cleanup implementation collects every signal outcome and attempts every target through an awaited path, discovering descendants even before readiness. Permission errors are retained and can only coexist with successful cleanup after terminal liveness checks prove no owned processes remain. A zombie-only process group can explain macOS `EPERM` ([XNU signal implementation](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_sig.c)); the exact target of the earlier local failure was not captured. File, directory and final-report-reserve boundary fixtures pass in the subsequent local smoke; they do not substitute for committed Linux evidence.

## Linux process-exit observation

[Run 39645120640](https://github.com/realkarych/kora/actions/runs/39645120640) on `e326b7c4a8964bb8d09c79519421fdf141f60328` retained four complete trials and then failed cleanup with only the generic name `Error`. Browser/server exit codes were zero, no owned live processes or proxy sockets remained, and runner descriptors/processes returned to baseline. This artifact cannot identify the exact failing cleanup stage and is not a baseline. Reports now retain bounded stage, error code and message, plus bounded server output.

A deterministic real Linux diagnostic opened a child status file, terminated/reaped the child, then read the open descriptor and received `ESRCH`. The [Linux proc implementation](https://github.com/torvalds/linux/blob/master/fs/proc/base.c) documents this behavior in `proc_single_show`. Process observation now treats `ESRCH`, like `ENOENT`, as disappearance; other errors still fail. This fixes a concrete sampling race but does not retrospectively prove the generic failure was that race. The complete workload must pass again with diagnostic evidence. Peak aggregation also now includes every retained warm-up, post-GC and terminal checkpoint; margins are unchanged.
