# Native macOS fixture release

Date: 2026-11-05. Implementation issue: [#751](https://github.com/realkarych/kora/issues/751). The project owner approved adoption and the two exact development-guide changes under [#302](https://github.com/realkarych/kora/issues/302#issuecomment-6657834169). The [implementation plan](https://github.com/realkarych/kora/issues/751#issuecomment-6657826483) records the boundaries. This is test-fixture behavior, not production artifact-provider behavior or a cause-specific fix for the historical CI refusals.

## Ownership and admission

The existing pressure controller holds the private directory lease and directly owns inventory commands and one native helper at a time. Cleanup first settles the workload child and any earlier native intent. A helper has no subprocesses. The controller validates the owned image and current attachment, persists the request before spawning, persists its exact process identity before stdin activation, and supplies a shared monotonic deadline. The helper checks its registered identity, request/fixture/controller binding, bounded activation and deadline before loading DiskArbitration or creating native objects.

A single 30-second release budget includes controller inventory, helper work and final attachment inspection, with five seconds reserved for process settlement. Existing outer recovery and test deadlines remain unchanged. Linux keeps its existing release operations and version-1 wire serialization.

The helper uses public `DADiskUnmount` on the exact mounted volume with option zero. A successful callback must be followed by a fresh unchanged whole-device/entity binding and an unmounted volume before option-zero `DADiskEject`. An already-unmounted attachment skips unmount. Eject success still requires fresh attachment absence. No force, sudo, fallback eject command or additional dependency is introduced on macOS. Release calls stay public; under #886 the helper also requires the exported non-public `DADissenterGetProcessID` to record a refusal's reported process, as the [Eject refusal record](storage-pressure-eject-refusal-2026-11-06.md) explains. A missing symbol fails helper binding before any native request.

## Fixture records and recovery

New macOS manifests use version 2 with an explicitly present nullable `native` field. Its request version 1 contains an exact request ID, fixture nonce, image device/inode, creator controller identity, phase, whole device, volume, complete entity list, monotonic deadline, explicitly nullable helper identity and explicitly nullable outcome. The helper identity is registered before activation. Legacy version-1 records cannot carry a non-null native request or native sidecars. Legacy recovery must meet all existing process/command and image identity guards, then writes version 2 before native submission.

The outcome version 1 contains request ID, phase, helper identity, `success`, `refused` or `not_requested`, a native uint32 code when requested, an explicit CF-closure witness and bounded text-presence/truncation flags. Since #886 it also has defaulted nullable `dissenter_pid` and `dissenter_comm` fields, set only for a refusal; an older record without them means not recorded. Refusal is distinct from success even if a dissenter reports code zero. Success requires code zero. `not_requested` is published only by the exact helper before any native submission and after all created CF objects are released; the parent never infers it from an exit status.

The helper compares the callback target with the requested disk using `CFEqual`, unschedules its run loop and releases its disk/session before publishing a result. A missing, malformed, stale, wrong-phase, wrong-helper or non-closed result stays unknown. The parent accepts a regular single-link same-user mode-0600 result of at most 8 KiB, with unchanged identity and size around the read, and requires actual helper-process settlement. Recovery can commit a matching completed result after a lost command response without inventing an exit status. Neither that result nor a helper exit establishes physical device absence.

Unknown completion blocks subsequent image mutation, resource-closure claims and further native experiments or CI retries. The owner retains the manifest and original failure evidence. Known completed refusals can use existing ordinary recovery after the blocker closes, under the same identity guards. There is no adoption of the prototype's separately authorized old-witness recovery.

**Amendment dated 2026-11-10 ([#1241](https://github.com/realkarych/kora/issues/1241)).** The helper fixes its cutoff, the earlier of the request deadline and 25 s after admission, before submission. The completion callback takes its own reading of the helper's time source before storing anything. A reading at or after the cutoff stores no result, the helper reports unknown completion and publishes no record, and the controller and recovery treat the missing record as unknown, as before. A reading before the cutoff keeps its completed result even if the run loop returns later. The rule applies to unmount and eject alike. The time source is injected through the helper's constructor; boundary tests pin the callback's reading to exactly the cutoff and to the preceding representable value while DiskArbitration requests run on a real owned image. Record formats, deadlines and the publication order after CF closure are unchanged.

## Private and public diagnostics

A borrowed dissenter CF string is copied through at most 256 UTF-16 units before conversion and produces at most 1 KiB of private UTF-8. It is written only to `native-text.bin`; helper stdout/stderr stay in distinct private files and are not copied by qualification's public artifact collector. Native result metadata is at most 8 KiB and its correlated committed value is retained in the manifest. The fixed public native note contains only summary version, phase, result, recorded-completion and recorded-CF-closure flags, numeric code or unknown, and since #886 the reported process's PID and tokenized comm, `none` or `unknown`. It contains no raw CF text, private paths, other process IDs or arbitrary error text. Existing holder observation remains a separately bounded diagnostic with its existing disclosure boundary.

The first exception note is a value snapshot; a later manifest update does not rewrite it. Recovery summaries accept strict manifest versions 1 and 2 while retaining their existing fixed projection and 8 KiB bound. This scoped approved extension supersedes only the earlier diagnostic slices' prohibition on new native observations; historical failed and unknown results remain failed and unknown.

## Verification and limits

Independent correctness, security and performance review cover the shared controller/helper/recovery and disclosure boundaries before real native disk tests. Strict source checks and focused regular-file/state tests cover explicit records, substituted targets, pending registration, settled helper without a matching result, legacy sidecars, lost responses, immutable notes and private-text bounds. Real helper admission failures cover invalid activation, expired admission, changed controller and unregistered helper before any native call. The existing real pressure-owner tests retain normal release, occupied-volume refusal and retained ownership, interruption, cancellation, deadline, child/parent failure and recovery. The intentional refusal test checks an actual native phase/code and a settled helper, then requires physical closure after the blocking process exits.

TM-06/07 cover private content, TM-08/12 truthful evidence and required gates, TM-09/11 exact target identity and recovery, and TM-10 bounded owned resources. Same-user metadata is not a hostile-process sandbox. No new actor, privilege, production authorization or provider contract is established. No latency, RSS or leak-freedom guarantee is inferred from the change.
