# IR document envelopes and materialized graph measurements

Checked 2026-10-23 for [issue #239](https://github.com/realkarych/kora/issues/239), the document-model part of [#218](https://github.com/realkarych/kora/issues/218). This record describes structural admission and model-only measurements. It establishes no scheduling, semantic validation, public diagnostic conversion, provider admission or payload-contract implementation.

## Structural surface and ownership

The eight node records form the actual discriminated `Node` union. Their source-owned output-role metadata supplies both validation and generated-schema constraints, including validation of each role's complete output declaration. Agent and command nodes refuse renamed or duplicated fixed-role types; human-input and wait-event nodes permit only their fixed role. Timer and branch nodes retain authored optional output declarations for later semantic refusal. No role, predicate, interval or overlap default is inserted.

`GraphBody` requires a nonempty stored-node map. `Subgraph` adds its input/output declarations, retry, limits and source. `Graph` owns the shared subgraph registry and graph-only attributes. Composition keeps registry references as strings; it does not expand instances or resolve cycles. Every constrained named map derives its key schema from its actual scalar annotation through the existing map hook. In particular, both actual `GraphDocument` schema modes refuse unmatched type-contract names; standalone Pydantic map-schema fallthrough is not reused as the document contract.

`GraphDocument` retains only a count of ignored root keys. The inspection helper exposes that count before nested validation; parsing discards ignored names and values without visiting their contents. Root extensions retain their established bounds. The raw `$schema` string retains its URI annotation without normalization or resolver authority. The Python spelling `schema_` remains an ignored root key.

`Provenance` is an explicit open data-bearing model and standalone canonical-export root. Known fields retain their types, partial snapshots remain raw objects, and arbitrary JSON members use iterative detachment. Its `x-` members are open informational data, independently of the bounded record-extension policy. Canonical helpers support only `IrRecord` and this explicit provenance shape. Existing protocol, extension, API and provider boundaries are unchanged.

Snapshot differences with results held identified record allocation and exported mappings/arrays as the dominant live allocations; those diagnostic snapshots do not replace the retained-resource protocol. The final exporter retains no field-layout cache, and preservation tests for different omissions in both encounter orders, reused instances, concrete subclass aliases and exact field/map byte order remain.

Phase sums from the existing corrected-profile JSON attribute approximately 5.70 ms per cycle to the predecessor 40 roots, 0.30 ms to the trigger and 10.14 ms to the supplemental rotation.
