# Saved type-schema validation evidence

Date: 2026-10-30. Implementing [issue #473](https://github.com/realkarych/kora/issues/473), a scoped part of MVP work item 3. This record describes the boundary and evidence method; actual commands, revisions, CI artifacts and independent review results belong to the PR.

## Delivered boundary and dependencies

`validate_type_schemas` accepts a structurally validated `GraphDocument` whose caller-owned maps remain unchanged during the synchronous call. Every supplied custom schema and recognized revision-1 built-in is checked, including unused contracts. The four fixed built-in schemas are byte-identical copies of the published artifact schemas, shipped inside `kora.ir`. No authored filename selects a package resource. Unknown built-in pairs fail closed.

The pass owns schema-position traversal, safe keyword projections, closed reference lookup and diagnostic collection. `schemas_valid` covers only this boundary. Raw document admission, inline node/form/parameter schemas, inherited effective compatibility, installed behavior support, namespace ownership, edge assignability, CEL, public surfaces and aggregate materialization remain outside it. It neither validates artifact payloads nor acquires execution authority.

The existing locked `jsonschema==4.26.0` and `referencing==0.37.0` set is promoted from optional conformance dependencies to core dependencies without version changes. Existing development stubs provide typing. The real draft-2020-12 metaschema runs over per-keyword views after typed shape admission. Child schemas are replaced by boolean placeholders and visited iteratively; unconstrained annotation/default/const/enum contents never enter native validation. Simple-type alternatives are admitted only as the seven unique standard names, avoiding native `anyOf` error accumulation for an arbitrarily wide malformed array. Required-name arrays collect malformed members and duplicates independently. Map entries are validated separately so one regex capacity failure cannot prevent other entries from being checked.

Fixed representations preserve values, equality and JSON kinds while preventing native messages from recursively printing authored containers, large integers or text. Native error iterators are consumed incrementally and closed. Regex syntax uses the explicit regex-only format checker; compiler `RecursionError`, `OverflowError` and `ValueError` are converted only for the regex-bearing keywords. Other unexpected failures propagate to the caller's existing error owner. Optional URI-format packages do not influence acceptance. URI format annotations alone establish no extra guarantee; operational reference authority and dialects have their own checks.

The [upstream validation documentation](https://python-jsonschema.readthedocs.io/en/stable/validate/) and [JSON Schema 2020-12 core specification](https://json-schema.org/draft/2020-12/json-schema-core), checked 2026-10-30, explain the explicit format checker and static behavior of a `$dynamicRef` whose initial target is not a dynamic anchor. This pass admits only empty/JSON Pointer fragments, so anchor declarations add no authority. Deprecated `$recursiveRef` is checked for saved closure without activating old-draft behavior. Root `$id` creates no alias; nested resources remain refused. Local and exact saved artifact-URN references use point lookup, never retrieval or recursive expansion. Targets inside data/unknown extensions are refused.

## Blocking evidence

`test_type_schema_matches_real_metaschema` compares an ordinary valid/invalid corpus with the actual pinned `Draft202012Validator.check_schema` using the same explicit format checker. It includes mathematical integers, booleans in numeric positions, huge integers, malformed containers, duplicate names, regexes and every schema-child keyword. Separate regressions exercise independent failures within an object and within a map/array, unsupported dialects, nested resource IDs, strict URI/JSON Pointer decoding, false schemas, cross-contract cycles, missing saved built-ins and unused contracts. A byte-for-byte before/after export verifies caller data is not mutated.

Deep malformed `title`, `type` and `required` values, schema depth 1,200, wide invalid type alternatives, and regex nesting/overflow/over-4,300-digit repeat cases cannot escape as native errors. The latter coexist with other faults, proving continued collection. Schema keys are masked as `<field>`; paths stop at a safe ancestor after 64 segments, and long contract identifiers use the existing ancestor fallback. Dense faults retain at most the existing 1,000-error/one-MiB collection while every omission still makes the result invalid. Existing collector tests preserve the combined-byte obligation.

`test_type_schema_catalogue_is_published_unchanged_in_core_wheel` compares all four resources against their normative publication and checks unconditional dependency metadata. `test_type_schema_validation_works_from_installed_core_only_wheel` installs the session-built wheel and its locked core dependencies offline into a fresh environment, then imports and executes the pass through the installed package without conformance extras or repository imports. The existing session-wide wheel fixture is reused.

`test_type_schema_validation_releases_owned_references` retains the result while weak references prove document/graph/contract release for both outcomes, checks that safe container projections are gone after collection, then proves diagnostics release when the result is dropped. No task, descriptor, transaction, child process or persistent resolver belongs to this pass. `test_type_schema_logging_is_content_free` exercises INFO completion events at DEBUG configuration and verifies schema/reference markers and stdout remain absent. `test_type_schema_result_survives_unavailable_sink` checks unchanged results under blocked/broken real transport, its existing queue bounds and released writer on shutdown.

## Diagnostic observations and limits

`test_type_schema_resource_observations` uses existing Report/Sample support and the JUnit property `type_schema_resources`: 1/100/1,000 schema positions, depth 1,200, 1,000 shared references and 3,000 invalid alternatives. Input construction is excluded; each workload receives one warm-up, three untraced timings and six mixed memory batches with post-GC current/peak heap and available RSS. Exact schema/reference counts are blocking; elapsed time, process heap and RSS have no threshold and establish no bounded-time or leak guarantee. macOS RSS remains unavailable through this collector.

Traversal visits schema positions once without expanding references; capped location tuples avoid depth-squared diagnostic paths. Point lookup costs include total URI/pointer characters and token lookup, separately from schema count. Per-call roots, registry views, projections and reference-cache entries scale with supplied input and are released; the bounded diagnostic result survives independently. The standard-library regex compiler retains an entry-bounded cache of patterns, compiled programs and potentially string views. Its entry bound is not a byte bound for arbitrarily large patterns. This dependency-owned state is intentional and excluded from per-call release claims. No new whole-document quota, regex time/space bound or interruption guarantee is introduced.

Observed local diagnostic results remain in the revision-labelled PR evidence; failures are not replaced by favorable reruns. Material unexplained growth, retained component resources or a contract defect triggers bounded investigation under the existing policy. No CI lane, numerical acceptance gate, mock, skip or suppressed static check is added.
