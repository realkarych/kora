## Decision and implementation

Existing ASCII canonical JSON determines logical value identity, including the equivalence of a valid materialized surrogate pair and its astral character. Preserving every Python code-point spelling instead would require a new identity decision because the existing canonical bytes already equate them. The accepted representation preserves lone surrogates and refuses decoded-key collisions rather than silently dropping a member. NUL, arbitrary exact integers within the explicit byte budget, finite float kind/signed zero, omission, map/list order and original reference roots survive.

`kora.db.graph_values` prepares both canonical texts and version 1 together, and classifies raw rows into explicit legacy or decoded values. `kora.db.graph_value_json` owns iterative rendering and strict parsing. The shared physical discriminator is nullable; NULL never infers new interpretation. Unknown versions and malformed/mixed pairs refuse. Migration 0007 only adds that discriminator/check; it preserves old logical values and unconditionally refuses downgrade before mutation. No current defaults, provider objects, validity claim or execution permission enter this foundation.

## Construction bounds and limits

The caller supplies positive aggregate inner-text capacity B. Rendering reserves both container delimiters before making an iterator/frame. It visits one member at a time, reserves separators and key syntax, and counts each escaped character before calling the scalar string encoder. It never materializes a full export, pending-entry list or oversized string and then checks it. Exact native dict/list/scalar types keep traversal free of caller-defined iteration or conversion. Active container identities reject cycles; existing IR admission owns repeated aliases within each open field, while separate fields may share materialized objects before their independent encoding.

Integer bit length rejects magnitudes beyond a capacity-derived bound before magnitude copies or decimal conversion. A rational upper bound on log10(2) handles clear fits; a power-of-ten comparison settles the boundary before the existing arbitrary-integer serializer runs. Its temporary integer capacity is derived from the remaining byte budget. Decimal parsing uses bounded nine-digit chunks and exact integer arithmetic. Large-integer conversion is not claimed linear-time. Finite binary64 scalar rendering has fixed maximum size independent of caller input length.

Decoding checks exact representation types, aggregate ASCII length and ASCII admission before expanding either member. An explicit frame stack handles depth without interpreter recursion. The standard JSON decoder is invoked only at a proven opening quote to decode a single string; number grammar and container state remain explicit. Each object retains its decoded keys to refuse duplicates, including surrogate-pair collisions. Complete bounded re-encoding rejects alternate whitespace, escaping, numeric spelling and trailing data. No recursion limit or global integer-conversion setting changes.

Traversal state, decoded objects, duplicate-key sets, fragments and scalar temporaries are derived from admitted syntax/scalar bytes. This establishes a representation/work ownership bound, not heap bytes equal to B or an RSS/latency guarantee. Map hashing and arbitrary-integer conversion retain their ordinary costs. Outer JSON strings add at most `2B + 4` textual bytes for the pair; PostgreSQL/SQLite representation, driver buffering, whole-row fields and raw acquisition remain separate. A trusted caller can choose an impractically large budget; this foundation selects no public quota or backend-compatible maximum.

Encoding occurs before write transactions. Raw row reads remain unchanged except for the discriminator field. Tests leave the read context, assert connection checkout and unit ownership are zero, then exercise successful and refused decode. Full production acquisition, publication, complete-contract construction, interpretation checks, authorization and budget selection remain pending under #593; codec success alone cannot activate deployment or execution.

The construction-order regression uses the standard profiler as an observer of real calls, without replacing behavior. It checks that over-budget strings/integers do not reach their full renderers, containers refuse before a child value is visited, and an over-budget pair never reaches string decoding. This is a deterministic admission-order check, not a new numerical measurement method. Exact boundary tests additionally exercise both-member exhaustion and escaped, wide and deep shapes.

Pure representation helpers add no executable entry point, logging sink or durable event. They return fixed content-free internal failures. Existing metadata migration diagnostics remain responsible for start/finish/failure events; changed-head migration/observability tests cover that owner. Payloads, names, schema values and exception-specific parser text are not public diagnostics. Threat coverage remains TM-01 namespace access, TM-04/TM-10 input/resource admission, TM-06/TM-07 diagnostic content and TM-11/TM-12 immutable identity/interpretation. No new actor or containment claim is introduced.
