## Bounded diagnostic boundary

The duration case keeps its original elapsed-time sample before any added diagnostic work. Both cases snapshot completion and journal byte size before teardown; no additional journal contents are read. After both owning contexts close, the existing capture finishes with its unchanged 1 MiB capacity and cleanup deadline.

Assertion messages retain the latest 16 selected records, a count of omitted records, and explicitly separate pre-teardown facts from post-teardown diagnostics. Only the existing `runtime.local.workspace`, `runtime.local.command_stop`, `runtime.local.capture` and `runtime.local.command` event names are admitted. Keeping the tail prevents early busy/refused records from displacing later stop/capture/observation evidence. Each event has a fixed outcome allowlist, including successful command `observed`. Numeric fields are only `waited_ms`, and for capture also `retained_bytes` and `observed_bytes`; values must be finite, nonnegative and at most the signed 64-bit maximum. Invalid values become a fixed sentinel. No unknown string, complete record, path, identifier, argv, token, digest, exception text or payload is rendered.

## Reading the evidence

Pre-teardown unresolved completion plus a corresponding unresolved-stop event localizes the refusal to domain closure, without identifying the underlying census obstacle. Confirmed stop with unsealed/write-failed capture points to capture; `journal_unavailable` points to persistence. Confirmed stop and complete captures followed by refusal narrow investigation to assembly/admission, but do not identify record capacity specifically. Events collected after teardown can include teardown work, and missing best-effort events prove neither absence nor success.

Local macOS checks passed all four selected cases in 0.89 seconds: the duration case, both capacity cases and `test_observation_diagnostic_tail_preserves_late_stop_and_observation`. The latter uses the real logger and capture to verify that 20 early refusal records cannot displace the later confirmed-stop and successful-observation records. The no-suppression architecture suite separately passed all 21 cases in 9.60 seconds. Final checks and one ordinary final-revision CI, including the already-required changed-test repetition job, are recorded in the PR. No extra repetition campaign is added. A failure-free run remains inconclusive about #1469's recurring root cause; it is not a runtime repair claim.

## Full-disk capture evidence extension

Diagnostic [CI 43405991546](https://github.com/realkarych/kora/actions/runs/43405991546), attempt 1, tested merge `9520ecf96739ddab1c630f28ee4dce9502026661`. Both Linux local-runtime lanes and the required changed-test repetition passed. All 19 observation-module cases passed on macOS too. The macOS lane instead recorded 733 passing cases and one failure in `test_command_capture_on_full_disk`: the capture seal task never appeared before the existing ten-second condition deadline. The later fixture unmount reported a busy resource. The workflow finished failed after 20 minutes 58 seconds, including scheduling and dependent jobs; no unchanged rerun was made. [#1478](https://github.com/realkarych/kora/issues/1478) retains the failure and the owner-approved diagnostic extension.

The additional evidence does not identify the busy mount's holder or establish a runtime cause. Before unwinding a failed wait, the test adds fixed owner exit-observed/reaped/error-present flags, domain-stop and capture-seal task states, capture presence, ended/writer-alive flags and bounded observed-byte counters to the original error. The owner lock is attempted without waiting; contention returns a fixed unavailable state. No process probe, completion retry, join, signal or extra I/O occurs. Queue, high-water and settled getters are omitted because they acquire a blocking private lock. Exit not observed does not prove a live process; writer alive does not prove an I/O call is active.

After the owning session contexts finish, the original wait error receives the same latest-16 event projection from the shared test support helper. If session-context cleanup replaces the raised exception, the pre-teardown note remains on the original exception in its chain and no completed event tail is claimed. The tail precedes the existing directory removal and later host-fixture unmount; it certifies neither of those cleanup operations, which can still fail with the original error retained in the exception chain. If event collection itself fails, an exception group retains both the original failure and the collection failure, with a fixed collection-failed note. No error is converted to success and cleanup is unchanged.

`test_capture_diagnostics_preserve_failure_without_private_content` uses a real command and the existing held native writer to observe an unfinished seal, then releases it and completes cleanup. The original assertion message survives, private output is absent from both notes, and the later event tail stays separately identified. Together with the existing observation regressions, five focused local cases passed in 1.01 seconds. The real full-disk host fixture is exercised by supported-platform CI; it is not installed in the local development environment.
