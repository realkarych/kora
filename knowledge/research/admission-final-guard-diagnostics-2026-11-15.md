The diagnostic delivery in [PR #1574](https://github.com/realkarych/kora/pull/1574) passed complete PR and master CI. Separate required CI executions subsequently recorded the exact final deadline branch for the SQLite/distinct case: [run 43650422115](https://github.com/realkarych/kora/actions/runs/43650422115) on Python 3.11 recorded 10.17666 seconds, and [run 43652883986](https://github.com/realkarych/kora/actions/runs/43652883986) on Python 3.15 recorded 10.25254 seconds. These observations establish each final expired-deadline path; they neither quantify profiler overhead nor prove historical native closure. Earlier failures and the rejected comparison remain failed or incomplete as recorded above.

The owner [approved one repair attempt](https://github.com/realkarych/kora/issues/1562#issuecomment-6886005913) after independent correctness, security and performance plan review. The original successful source cases retain the complete three-node graphs, same/distinct versions, independent cap version, values, immutable-copy assertions and real ten-second operation deadline. Their new observer requires the first real execution-contract checker entry to follow exactly one completed checkout, with no outstanding checkout or database unit. It then restores the prior profiler immediately, before that checker runs. A successful context must have observed that entry. The preparation must still return without another checkout; it must pass production's original cancellation checkpoint and deadline guard. The test checks hook restoration both before leaving the context and afterward. Existing pre-checkout allowance refusals additionally verify restoration when no checker is entered.

The full observer and its safe refusal note are unchanged. The existing observation regression adds a distinct-cap final-deadline case on both real databases, publishing the same second graph as the successful source fixture. It asserts all seven entries in order, zero units at each, actual result construction, the original final refusal and both flags, unchanged metadata, exception identity, hook restoration and native closure after shutdown. All five existing same-graph outcomes remain. The loop continues to use real monotonic time with a nonnegative offset; the constructor-return hook only advances it to the original deadline.
