## Fixed population

`tests/measurements/test_conformance_lifetime.py::test_conformance_fixture_resources_are_released` executes three independent, sequential, long-lived parent processes. Each executes 80 cycles: two warmup traversals of success, failure, cancellation, recovery and shutdown; then 30 success, 10 failure, 10 cancellation, 10 recovery and 10 shutdown cycles. The total is exactly 240, including 30 warmup cycles. Every cycle creates and settles real helper processes, anchored directories, durable ownership and process domains. No synthetic zero-success baseline is used.

Success uses a real local RPC client process, tree reservation/acquisition, independently decoded process request replay, acknowledgement, observation, natural exit, pipe EOF and parent closure. The direct process request uses eight environment values of 55,000 ASCII bytes on even success cycle indices, otherwise no environment values. Its separately decoded equal replay has distinct strings. The real wire client uses four 55,000-byte values and two independently decoded equal requests. Thus admitted direct request copies contribute 880,000 value bytes; later the retained direct canonical request and two wire copies contribute 880,000 value bytes, plus their actual validated metadata. The unchanged 1 MiB execution snapshot gate still applies. Each client emits exactly 32,768 bytes on stdout and stderr, and the parent checks 65,536 captured bytes.

Failure preserves an actual typed conflicting-operation refusal and observes the nonzero exit of a gate with a missing executable. Cancellation cancels a caller after ordinary-operation ownership becomes visible, then joins the separately constructed replay without abandoning the underlying operation. Recovery starts an actual original parent, registers a live domain, observes and reaps that parent, and resumes the durable reference using the fixed recovery implementation. Shutdown alternates prepared and active domains. Actual direct-child waitpid reaping, recovered watcher disposal, exact invocation-directory absence, helper exit and weak-reference collection are independent of report counts.

The constructor-selected decision clock and existing integration limits are acquisition 30 seconds, cooperative 0.1 seconds, TERM 0.1 seconds, kill observation 2 seconds and drain 1 second. Shutdown/recovery advances the decision clock only at the existing phase frontier; native exit, group settlement and EOF remain real observations. Each cycle has one independent ten-second completion guard, with the existing five-second failure guardian. The entire three-parent command has one unchanged 600-second ceiling. These guards are failure bounds, not measured performance tolerances. Default-budget and FIFO/TERM-resistant adversaries remain covered by the foundation integration suite rather than multiplied across all 240 cycles.

## Allocation and resource observations

CPython tracemalloc starts with one frame before interpreter imports in each measured parent and recovery original parent. Exactly one first-bootstrap helper per independent measured parent also starts interpreter tracing before imports, for exactly three cold-import-inclusive helper records. Every other helper imports the unchanged fixed main normally and starts one-frame tracing immediately before main. Nested recovery-original-parent launchers never restart cold selection. Parent samples record the cold import peak, then reset the traced peak at each acquire/use/close boundary. An owned observer records current/peak traced heap, current native RSS, lifetime native RSS high-water mark, task/thread/timer/import counts, selector registrations, descriptors by kind, registered target/helper RSS and logical ownership inventories every 20 ms while a phase is active. The observer stops and joins before settlement; it never establishes settlement by polling for an unchanged count. The JSONL cap is 32,768 records of at most 4,096 bytes per parent, an artifact bound rather than an allocation gate.

Linux current RSS comes from `/proc/PID/statm` and native thread count from `/proc/PID/task`. macOS uses `proc_pidinfo(PROC_PIDTASKINFO)` with the exact six-uint64/twelve-int32 structure in the locally installed Apple SDK `usr/include/sys/proc_info.h`, checked on 2026-10-23. `pti_resident_size` supplies current RSS; `pti_threadnum` supplies native threads. `resource.getrusage().ru_maxrss` is separately labeled a lifetime high-water mark, with Linux KiB converted to bytes. Sampled native maxima are lower bounds at the declared interval; they are not exact instantaneous peaks. A process that disappears between inventory and counter read is explicitly counted as a departed counter, not assigned zero RSS or treated as closure proof.

Every fixed helper runs the unchanged helper `main` under a statically imported test wrapper. Closed discriminated records identify `cold_import` versus `mutation` trace scope and use distinct cold-current/cold-peak or mutation-current/mutation-peak fields. The report validates one cold record per measured parent and mutation records for every remaining helper. It records import time, total time, native peak bytes and pre-kernel-teardown descriptor/import counts for all helpers. Mutation-only current and peak allocations exclude the imported Python graph and are never called total heap, mixed with cold maxima or summed across processes. The native high-water capture occurs after main, before numeric-record serialization and interpreter/kernel teardown, so it is not an exact final-teardown peak. The observer descriptor is inherited only by the helper and never by the launch gate/target. Mutation claims remain held through helper kernel teardown. The wrapper is constructor-selected and passes the same mutation/claim/directory-handoff contract as installed and existing probe launchers. Ordinary workload children have native resource/exit/reap evidence; this method does not claim arbitrary target-application Python allocation coverage.

Settlement is recorded each cycle, with eight retained samples and tracemalloc snapshots per parent at cycles 10 through 80. GC runs only after affirmative owner settlement and an explicit completion-callback turn. A bounded per-cycle set retains exact helper/target/original-parent identities independently of the strong lifetime owner. Settlement checks current host/boot/PID-namespace scope and actual native identity absence (or a positively different reused identity), fails on missing/unknown observations or live matching identities, and only then clears that set. An empty owner-derived PID list is not an absence proof. Exact tasks, live timers, selector registrations, descriptor kinds, native/Python threads, imports and recovery ownership must return to their observed warmed baseline. Weak references prove collection of the parent and independently decoded direct requests. GC-tracked ProcessLaunch, Context and traceback counts are recorded and must return to their warmed counts; allocation diffs retain the top 20 source paths. Bounded observer cycle records and snapshot objects are measurement-owned allocations and are disclosed separately from product retention. Numeric logical capacity reservations do not establish native/Python memory usage.

## Artifacts and decisions

The command writes the existing Report/Sample schema to a fresh private `KORA_MEASUREMENT_OUTPUT` path and stores all raw JSONL, helper records, parent stdout/stderr, state-root paths and heap snapshots in its sibling `.artifacts` directory. Failure preserves the private state root and every completed/raw sample; no failed or incomplete run certifies 240 cycles. The first complete data set is used to explain retained allocation paths and select justified numerical budgets before activation. No arbitrary heap, RSS or timing tolerance is preregistered as a measured fact. A replacement requires a documented source/method defect and preserves the original attempt; no retry-until-green is allowed.

The dedicated `tests/conformance/lifetime_full_disk.py` is explicitly collected only on Linux with `KORA_LIFETIME_FULL_DISK_ROOT` pointing to an empty, runner-owned, separately mounted tmpfs of 1–128 MiB. It verifies mount identity/type/capacity before filling to actual ENOSPC, and tests admission and prepared-process registration publication refusal. It preserves UNKNOWN and durable evidence after refusal, then proves actual process/helper cleanup. It never fills a host volume, substitutes EFBIG or uses a skip. The private full-disk directory is explicitly owned rather than recursively removed by TemporaryDirectory. UNKNOWN journals survive normal and exceptional unwind; operation cancellation/join is in an independent finally even if filler release or the failure guardian raises. The module verifies the empty mount once, allowing its two independently named private failure roots to remain for inspection. macOS execution does not certify this Linux-only case.
