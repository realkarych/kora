# CEL Rust lock and the chrono maintenance advisory

Checked on 2026-11-21 under [issue #1706](https://github.com/realkarych/kora/issues/1706). The [full master scan at 68d8598](https://github.com/realkarych/kora/actions/runs/44799853104) reported `RUSTSEC-2026-0543` on `chrono 0.4.45` in the copied Rust lock. The [RustSec advisory](https://rustsec.org/advisories/RUSTSEC-2026-0543.html) classifies the finding as informational and unmaintained, lists all versions as affected and lists no patched release. [PyPI](https://pypi.org/project/common-expression-language/) still identifies 0.10.0 as the current Python binding. Its Rust lock includes chrono.

The owner approved an exception for this advisory with an expiry of 2026-12-20. It uses `ignoreUntil` in the existing adjacent configuration for the copied Rust lock. The [pinned scanner loads adjacent configuration per directory and matches advisory aliases for an ignored ID](https://github.com/google/osv-scanner/blob/v2.7.0/docs/configuration.md#ignore-vulnerabilities-by-id). Other chrono findings and the Python and JavaScript lockfile scans retain their normal handling. The existing source-less root-crate override still applies to the unrelated CEL name collision.

Recheck the advisory and the binding's released Rust lock on the next binding release or at the exception expiry, whichever occurs first. Remove the exception when the binding has a qualified replacement without the dependency or the advisory no longer applies. The scanner resumes reporting the finding at expiry unless an owner approves a separate renewal.
