Its 83 packages are 82 crates.io packages with checksums and the source-less root crate `cel` 0.10.0. The CEL interpreter is the crates.io package `cel` 0.14.5. ## Behaviour baseline

- **Loading.** `import cel` loads `cel`, `cel.cel` (the native module), `cel.cli` and `cel.stdlib`, all listed in RECORD, and creates exactly one new `pyo3_runtime.PanicException`, a direct subclass of `BaseException`. Loading through `kora.cel_eval.binding` takes about 130 ms on an Apple-silicon laptop, most of it the command-line dependencies.
- **Exceptions.** Compile and evaluation failures surface as `ValueError`, `RuntimeError`, `KeyError`, `TypeError`, `IndexError`, `ZeroDivisionError`, `OverflowError` and the panic class. Their messages can contain expression text. A function the binding lacks fails only at evaluation, with `RuntimeError`.
- **Logging.** The binding calls `pyo3_log::init()` and logs to the Python logger `cel`; in the probes only a failing context function logged, at WARNING, with the exception text in its message, and no child logger of `cel` was created. A parser panic from deep nesting is raised by PyO3 outside that path and logs nothing. Its Rust panic hook writes a few unframed lines to file descriptor 2: a blank line, `thread '<unnamed>' (<thread id>) panicked at <builder cargo path>/cel-0.14.5/src/parser/parser.rs:93:17:`, the message `Formatting argument out of range`, and a note on `RUST_BACKTRACE`; with that variable set, a backtrace follows. None carries expression text.
- **Context.** A callable in an evaluation context is registered as a function.
- **Iteration.** Iterating over a map visits its keys in an order that changes between evaluations.
- **Durations.** `duration()` of a string clamps silently to about ±292 years (±2^63 nanoseconds), so `duration('9300000000s') == duration('9400000000s')` is `true`; arithmetic and timestamp differences produce durations beyond that, and timestamps beyond the cel-spec range are refused.
- **Installers.** pip records the bytecode it compiles under `cel/__pycache__/` in RECORD without hashes, which the loader accepts; uv records no bytecode.
- **Conformance.** 37 of the 1,005 included conformance cases deviate, in the twelve categories of [ir.md section 7.8](../specs/ir.md#78-conformance).

## Residuals

- The loader checks that the binding's files match their RECORD hashes, which detects drift, not tampering. It does not check the bytecode cache under `cel/__pycache__/`, which Python runs instead of the checked source when a cached file's header matches the source or the file is an unchecked-hash `.pyc` (PEP 552); it refuses symbolic links there as everywhere in the package. It cannot see another `sys.meta_path` finder, and it does not check the pure-Python import chain above.
- A yanked pin is detected by no check; it stays a manual re-check.
- The Rust standard library and toolchain inside the native module are covered by neither the crate lock nor the SBOM.
