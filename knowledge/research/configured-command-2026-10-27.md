## Implementation and ordinary checks

The root command lazily imports the optional conformance composition. The parent owns invocation startup, child activation, private result/registry/lifetime channels, stop/reap and cleanup recovery. Only the isolated child reads user files or imports the selected provider and explicitly installed pytest fixture. Three socket entries live in a recorded subordinate tree; the parent verifies and unlinks them before releasing inputs. The original startup deadline reaches the private READY transition; healthy idle execution has no inherited startup timeout. EOF immediately fences and stops resources, while a core-only outcome latch delays the immutable invocation report until final classification or the unchanged close deadline. Late teardown failure cannot become success, and uncertain closure preserves private recovery state.

The complete six-suite inventory and two nonempty configurations now run through `kora conformance` from actual built and installed wheels. Existing installed-child negative tests remain for fixture authority, private report bounds, skip/xfail rejection, output draining and storage/native-work failure. Named public tests cover selected imports, missing extra, malformed configuration, wrong fixture bundle, schema mismatch, content exclusion, real SIGTERM/SIGINT cancellation, explicit close and cleanup after actual original-parent death.

Distinct owner regressions cover bidirectional listener operation after descriptor transfer, interrupted receipt and the original startup deadline, connected but blocked metadata loading, healthy execution beyond startup expiry, delayed teardown after lifetime EOF, retained endpoints with late FAILED publication, failed/blocked publication, missing outcome, scoped close and repeated immutable reports. Crash tests distinguish pre-unlink retained socket entries, post-unlink recovery and substituted entries. CLOSED recovery certifies resource closure only, not the earlier conformance result.

Local targeted checks on CPython 3.11.17/macOS 27.0.1 arm64 passed the six public suites plus two configurations (8 cases), public negatives/missing extra (10), startup interruption (2), readiness/teardown/blocked bootstrap (3), outcome ordering (8) and retained-endpoint publication (1). These are dirty-source development observations; the implementation PR supplies revision identities, complete required final-head CI and any later corrections. Linux and macOS final-revision checks are separate from these local results.

## Frozen-clock test cleanup

The next run at `56ea004` ([CI run 40491028077](https://github.com/realkarych/kora/actions/runs/40491028077)) passed both Linux conformance groups, all public-command groups, storage lanes and measurement producers. macOS conformance again reached the unchanged job timeout; its artifact still contained collection only. The whole workflow lasted 11m09s, including dependent failed aggregates. These observations do not locate a native stalled test or establish that elapsed test work alone caused cancellation.

Real-process experiments on Linux x86_64 with CPython 3.11.17 then found two test-harness waits that a frozen injected clock could never release. Their corrections change no production code, workflow configuration, supported environment, deadline or limit.

The first was in the startup regression's finalizer. It cancelled the command and advanced its injected clock before cancellation established the close deadlines, then joined the command before disposing its owner. With the bootstrap helper waiting for a FIFO writer, the close started at the already advanced instant, so its cooperative deadline stayed a pending clock waiter that nothing advanced past. A diagnostic variant of the original finalizer recorded that state five real seconds after the advance: the command was pending, one helper was live, and the cooperative deadline was the only clock waiter. The finalizer now disposes the owner before joining the command, and that join is bounded to five seconds. A new case raises an early failure while the helper waits for the FIFO writer, then checks actual task and helper settlement through the same finalizer. Against the original finalizer that case did not finish: at 40 seconds pytest's fault handler showed an idle event loop, and an external 60-second bound stopped the run. With owner-first disposal the file's three cases passed in 4.66 seconds, that case in 0.23 seconds; this completion is the evidence that disposal settles the helper and the command.

The second was in the installed-child harness. After lifetime EOF, a fixture can withhold the result during teardown; result readability, endpoint completion and invocation completion then all wait for cleanup deadlines that a frozen clock never reaches. A real installed delayed-teardown regression waits for the fixture's teardown signal, then requires the harness to fail with a channel error within 20 seconds while the fixture still withholds its result. Against the original harness it received that signal and then failed with a bounded `TimeoutError`. After the correction it passed in a 9.23-second test call with an earlier text of the test whose barrier receive was unbounded, and in an 8.16-second call inside the complete-file run with the final text, which bounds that receive to 30 seconds. The harness now reuses the existing `ProbeClock` and starts system-time progression once closure start is observed. The clock-progress task is owned, cancelled and joined with the existing tasks. The test disposer only broadens its annotation to accept that existing clock implementation.

Healthy execution before closure remains untimed. When lifetime EOF starts closure, the installed harness now lets the unchanged cooperative, TERM, kill-observation and drain limits elapse in real time, as the production command does; a child that takes longer than the five-second cooperative grace to report its result is terminated instead of being waited for indefinitely. The storage-phase and `stop_on_feedback` paths still request closure themselves and explicitly advance past the cooperative grace, so their children receive TERM at once rather than after the production grace. The accepted consequence is that every installed case is now bounded in real time by those unchanged limits after closure starts, and a child that reports its result but needs TERM to exit can now satisfy cases that assert only a nonzero return code; tightening those assertions is an optional follow-up. A local diagnostic comparison of the 49 pre-existing tests in `tests/conformance/test_installed_conformance.py` found no growth near that grace on a shared two-CPU host: the largest per-test increase was 1.84 seconds, and summed JUnit durations were 303.29 seconds before the change and 292.53 seconds after it. These local reproductions justify the test corrections; they do not show that either wait caused the macOS timeout, whose stalled test remains unidentified. Final-head native CI remains required.

## Listener transfer observation

Checked on 2026-10-27. A local real-process bidirectional probe received premature EOF after the helper sent listening descriptors and exited before the parent acknowledged receipt. Keeping the helper's copies until the fixed `listeners_received` frame produced the expected reply; cancellation closes unadopted received descriptors while leaving helper settlement with its existing owner. The ordinary regression sends a fresh challenge through every accepted connection after transfer; queued bytes alone are insufficient evidence.

A [Dovecot developer report and maintainer response](https://dovecot.org/mailman3/archives/list/dovecot@dovecot.org/thread/7DWJHYFU5IUKMAMNLNYV7NGKAM53CHGJ/) independently describe premature EOF with macOS `SCM_RIGHTS` socket transfer and retaining the sender's descriptor until receiver acknowledgement. This is supporting portability evidence, not proof of a particular kernel cause or equivalence of the two applications. The kora change is justified by its own listener probe and fixed ownership transition. No timeout, suppression rule or process-replacement allowance changes.

## Preregistered command qualification extension

The existing `tests/measurements/test_conformance_lifetime.py` entry point retains 240 foundation and 420 listing cycles and adds 270 configured-command cycles: three independent persistent measured parents, each with ten warmups and 80 observed cycles. Warmup order is success, preparation failure, exercise failure, cancellation, explicit shutdown, crash/recovery, then four successes. Observed order is 30 successes followed by ten of each other ending. Two alternating nonempty secrets configurations exercise the real selected suite. Other active protocols retain their ordinary installed-wheel coverage.

Each cohort retains one `MeasuredLoop`. Cancellation cancels useful command work at an explicit fixture preparation barrier; shutdown instead calls the real lifetime client's `close(None)`. Recovery kills a separately owned original command parent, observes its exit and resumes fixed cleanup while the measured cohort survives. The original parent supplies a bounded pre-crash identity, helper-count, traced-heap and native high-water receipt; post-crash internal counters are unavailable. Original helper records are checked separately from recovery-cohort helpers.

The extension reuses `Observer`, `MeasuredIOHelperLauncher`, `NativeCounters`, descriptor classification, `run_cohorts` and the existing private-root archive collector. Parent tracing starts at interpreter startup with one frame. Sampling is every 20 ms plus phase/settlement checkpoints. Child tracing starts at explicit fixture-module import and excludes earlier dependencies/core imports; its barrier and normal-final records remain distinct. Cold-helper and mutation-only helper records retain their existing scopes. Native sampled peaks are lower bounds, and absent child-final counters remain null. Process-wide memory and timing are diagnostic; this method introduces no numerical leak or latency threshold.

At every cycle, require actual child/helper settlement, absent tracked identities, empty owned groups, no retained journal/claim, weak owner collection and no recovery-registry state. After all six paths warm, require identical descriptor/task/timer/watch/thread/import counts. Record every cycle, bounded samples, helper records and ten-cycle allocation snapshots. The bounded cycle evidence list intentionally remains in the parent and contributes to retained Python memory; allocator high-water memory alone is not a component leak.

Setup, fixture installation, warmup, execution, recovery, cleanup and report publication consume the existing qualification deadline established when the listing measurement module imports. In a whole-module run there is no fresh 600-second allowance.

CI shard amendment, 2026-10-28, awaiting explicit owner approval in PR #379: the [hosted measurement shards](conformance-lifetime-measurement-2026-10-23.md#hosted-measurement-shards-2026-10-28) run this measurement in its own nightly job and pytest process. Its 600-second cutoff therefore starts at that process's import and no longer includes foundation or listing time, and the CI sidecar's `seconds` and `remaining_qualification_seconds` refer to that shard alone. A local whole-module run keeps the shared cutoff. The population, per-cycle guards and cutoff value are unchanged. Existing individual deadlines and populations remain unchanged. `command.json` requires the complete 270-cycle population and raw-record accounting. Each cohort's actual removal/retention disposition is recorded; one failed archive does not suppress later archives or the failed sidecar. Unresolved roots remain private and are preserved for inspection.

The environment uses the locked editable core and an installed fixture wheel through the existing measurement `.pth` arrangement. This is instrumentation evidence, not the ordinary isolated full-wheel packaging proof. Source hashes, helper/parent observations and the shared deadline accompany the sidecar. Full instrumented qualification remains nightly/manual and mandatory for the exact release revision under the accepted schedule; it is not a per-PR merge gate.
