# Namespace-free authentication context

Implementation scope under [issue #534](https://github.com/realkarych/kora/issues/534), checked on 2026-10-31. The owner approved the dedicated logger/clock context for authenticate/revoke; the issue records the forwarded direct-answer receipt and [concrete plan](https://github.com/realkarych/kora/issues/534#issuecomment-6535960281). This scope is separate from HTTP transport, dependency adoption and routing proposals.

## Delivered boundary

`kora.protocols.authentication.AuthenticationContext` is a frozen value containing exactly the borrowed `ComponentLogger` and `Clock`. Authentication precedes namespace authorization, including installation-wide requests and credentials with no grants, so callers need no fabricated system/default/first namespace. Both authentication methods, static-token and authentication conformance callbacks use this type. External implementations adopt the changed public context contract; no compatibility cast or shim is provided.

The common `ProtocolContext` and all other provider families retain their existing fields and behavior. Token identity, grants/flags, digest storage, current reads, expiry, permanent revocation and recognized failure classification are unchanged. The new value creates no process, task, cache, database, secret registration or output sink and closes neither borrowed reference.

Direct authentication checks construct the narrow context from their owned capture logger/clock. The generic conformance driver may retain its internal `ProtocolContext`, but authentication-specific adapters construct a new two-field value before invoking the exact selected provider. This includes installed common failure, logging and configuration cases, not only six authentication-specific cases. Common assertions, names/order, eleven installed checks and ten direct injected checks remain. Other protocol callbacks continue receiving their original context.

Existing already-authorized fixture logger scopes remain verified. Removing the namespace field does not erase authorized logger context or establish API ingress isolation: clearing inherited context, request correlation, uniform HTTP errors, route authorization and actual handler integration remain with work item 11. This change activates no route, engine, fake composition, readiness or client behavior and adds no FastAPI/httpx or other dependency.
